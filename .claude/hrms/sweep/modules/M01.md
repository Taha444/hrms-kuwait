## 1. الاكتشاف — ما هو موجود فعلا
### الشاشات
شاشة دخول واحدة (رقم مدني + كلمة مرور)، وشاشة تفعيل 2FA منفصلة تُفرض على من يلزمه دوره قبل أي عمل آخر (`must_enroll_2fa`)، وCompanyPicker لمن يرى أكثر من شركة.

### المسارات (endpoints) — `backend/app/routers/auth.py`
```
POST /auth/login            دخول — يرد التوكنان + must_change_password + must_enroll_2fa
GET  /auth/my-companies     قائمة الشركات لمن يحتاج اختيارا
POST /auth/select-company   يصدر توكنا جديدا بـactive_company_id
POST /auth/refresh          تجديد access_token من refresh_token
GET  /auth/me               بيانات الجلسة الحالية وصلاحياتها
POST /auth/change-password  تغيير كلمة المرور — يُبطل كل التوكنات
POST /auth/reset-password   إعادة تعيين (manage_users فقط) — كلمة عشوائية لا يدوية
POST /auth/logout           يُبطل توكنَي هذا الجهاز فقط
```
2FA في `backend/app/routers/twofa.py` (`_verify_code` بنافذة TOTP قابلة للضبط، `consume_recovery_code`).

### الجداول
`users` (`failed_attempts` · `locked_until` · `is_active` · `status` · `must_change_password` · `totp_secret` · `totp_confirmed` · `totp_recovery_hashes` · `last_activity_at` · `tokens_valid_after`) + جدول إبطال التوكنات (`token_revocation.py`).

### الأدوار والنطاق
كل الأدوار الثمانية تسجّل دخولا من نفس المسار. لا مسار دخول منفصل بالدور.

### الإعدادات التي يعتمد عليها (`backend/app/config.py`)
```
idle_logout_minutes = 10     (افتراضي — 0 يعني معطّل، خيار صريح)
rate_limit_enabled   = True
MAX_FAILED = 5, LOCK_MINUTES = 15     (auth.py، على مستوى الحساب)
_RATE_MAX = 10 / 60s                   (auth.py، على مستوى IP)
TWOFA_REQUIRED_ROLES = {super_admin, company_owner, company_manager, hr, delegate}
```

## 2. المسار كما هو منفّذ
```
POST /auth/login
  → _rate_check(ip)                                    429 لو تجاوز 10 فشل/دقيقة لهذا الـIP
  → بحث المستخدم بالرقم المدني
  → فحص كلمة المرور — أو _dummy_verify (زمن PBKDF2 نفسه) لو الرقم غير موجود
  → غير موجود/خطأ  → failed_attempts++ → قفل عند 5 → 401 موحّد
  → صحيحة:
      locked_until سارٍ         → 423
      is_active=False/suspended → 403
      employment_ended          → 403 (انتهت الخدمة رغم is_active قائم)
      totp_confirmed=True بلا رمز → 401 {requires_2fa:true}
      رمز خطأ (وليس رمز استرداد صحيح) → failed_attempts++ نفس آلية القفل → 401
  → نجاح: failed_attempts=0، last_activity_at=الآن، تدقيق login
  → is_cross_company → قائمة شركات في الرد (بلا فرض اختيار فوري)
  → يرد access+refresh (sid مشترك) + must_change_password + must_enroll_2fa
```
### المسارات البديلة
- **فشل الدخول**: 401 موحّد الرسالة سواء الرقم أو الكلمة خطأ — لا يكشف أيهما.
- **قفل الحساب**: 423 بعد 5 فشل، مؤقت 15 دقيقة — يظهر فقط بعد إثبات معرفة كلمة السر الصحيحة (ترتيب مقصود، مُعلَّل في الكود).
- **حساب موقوف/معطّل**: 403 برسالة مختلفة (موقوف/غير مفعّل)، تظهر بعد إثبات الكلمة أيضا.
- **انتهاء الخدمة**: 403 — حتى لو الحساب `is_active` لم يُعطَّل بعد (قراءة حالة الموظف مباشرة، لا تعديل).
- **رمز 2FA خطأ**: 401، ويُحصى كفشل دخول على نفس عدّاد القفل الفردي (لا rate-limit الـIP وحده).
- **رمز استرداد 2FA**: بديل مقبول عن TOTP، يُستهلك بعد الاستخدام (لا يصلح مرتين).
- **تغيير كلمة السر**: يطلب الكلمة الحالية (تُحصى فشلا أيضا)، وينجح فيُبطل كل الجلسات القديمة (`tokens_valid_after`).
- **إعادة التعيين من الإدارة**: يرفض تحديد كلمة يدويا صراحة (400) — كلمة عشوائية تُعاد مرة واحدة فقط.
- **الخروج**: يُبطل توكنَي هذا الجهاز فقط (access + refresh إن أُرسل)، لا كل جلسات المستخدم.
- **التجديد (refresh)**: يفحص is_revoked وemployment_ended وenforce_idle_timeout بشكل مستقل — لأنه لا يمر بـget_current_user.
