---
description: مراجعة تغيير مقابل مواصفة HRMS V2.2
---

راجع التغييرات الحالية (`git diff` أو الملفات المعدّلة) مقابل المواصفة:

1. شغّل `bash .claude/hrms/scripts/antipattern-scan.sh .` على المشروع وحلل النتائج ذات الصلة بالتغيير.
2. حدد أي طبقة يمسّها التغيير واقرأ سكيلها: محرك / كتالوج / صلاحيات / مستندات / قوالب / واجهة / ترحيل.
3. اذكر **البنود المتأثرة بالمعرّف** (AC/RW/DOC/STR) — الجديدة والمهددة بالكسر معا.
4. لكل بند متأثر: هل يوجد اختبار آلي يغطيه في هذا التغيير؟ إن لا، **اطلبه صراحة قبل الدمج**.
5. افحص تحديدا هذه المخاطر المتكررة:
   - صلاحية عامة جديدة بدل صلاحية مفصولة
   - حد سياسة مكتوب في الكود بدل `policy_rule`
   - حالة طباعة تسربت لحالة الطلب
   - قالب جديد بدل Profile على قالب قائم
   - فحص أمني في الواجهة بلا مقابل على الخادم
   - مستند يُصدَر بلا `document_number` مستقل أو بلا snapshot
6. اختم بحكم واضح: **آمن للدمج** / **يحتاج تعديلا** / **يخالف المواصفة** — مع السبب المحدد ورقم البند.
