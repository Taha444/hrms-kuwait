البند المطلوب: $ARGUMENTS

اقرأ سكيلي `hrms-verification-protocol` و `hrms-defect-triage`، ثم اتبع الدورة كاملة:

## 1. اقرأ البند
```bash
python3 .claude/hrms/scripts/defects.py --show $ARGUMENTS
```
لو فيه تنبيه تناقض `!!` — تحقق من البناء الحالي قبل أي تعديل، ولا تصلح شيئا سليما.

## 2. أعِد إنتاج العطل
نفّذ خطوات `verify` المذكورة. **ممنوع الإصلاح قبل رؤية العطل.**
إن لم تستطع إعادة إنتاجه، قل ذلك صراحة واطلب البيانات الناقصة (الحساب، الشركة، السجل المحدد).

## 3. حدد الجذر ثم افحص التوابع
- أين مصدر الحقيقة لهذا السلوك؟
- كم مكان آخر يكرر نفس المنطق؟
- شغّل السجل وابحث عن بنود أخرى بنفس الجذر — **أصلحها معا**

اعرض قائمة البنود التي سيغلقها هذا الإصلاح قبل أن تبدأ الكتابة.

## 4. نفّذ الإصلاح
- في الجذر لا في العرَض
- على الخادم لا في الواجهة فقط
- مع اختبار آلي يغطي الحالة

## 5. اكنس الأبعاد الستة
لكل بُعد، اذكر ما فعلته صراحة:
- **الأدوار**: Employee · Branch Supervisor · Manager · HR · Accountant · PRO · Owner · Super Admin
- **الشركتان**: GUF و MUF — إلزامي، بلاغ API-01 يثبت أن السلوك يختلف بينهما
- **مسارات الوصول**: القائمة · الرابط المباشر · الـ API · Storage · Deep link · Back · Reload
- **اللغة**: عربي RTL و إنجليزي LTR — النصوص والأرقام والتواريخ والعملة
- **الحالات**: Loading · Empty · Error · Unauthorized · Success
- **الطبقات**: UI · API · Storage · DB · Export · PDF · Notification payload

## 6. أثبت الأثر
لو البند في مسار طلب: تحقق فعليا من سجل الحضور أو الرصيد أو قيد الراتب أو المستند أو المهمة أو الإشعار.
**حالة الطلب وحدها ليست دليلا.**

## 7. أغلق بدليل
```bash
python3 .claude/hrms/scripts/defects.py --set $ARGUMENTS fixed --note "<commit / ملف اختبار / مخرَج فعلي>"
```
وأغلق أي بند آخر أُصلح ضمنا بنفس الجذر.

اختم بنموذج تقرير الإصلاح الستة في سكيل البروتوكول.
