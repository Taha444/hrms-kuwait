المراجعة القادمة **مركّزة على البنود فقط وليست Audit جديدا** — بنص طلب المراجعة.

## قبل البدء
- **تأكد ألا تُرفع Build جديدة أثناء الـ Retest.** لو رُفعت، الاختبار كله باطل.
- سجّل: Commit SHA · وقت الـ Deployment · Migration Version — واستخدم نفس البناء طوال الاختبار.

## التنفيذ
لكل بند حالته `fixed` أو `verified`:
1. اقرأ خطوات `verify` في السجل
2. نفّذها **بالضبط كما وردت في البلاغ الأصلي** — نفس الحساب والشركة والصفحة
3. اكنس الأبعاد الستة من سكيل `hrms-verification-protocol`
4. لو فشل: `--set <ID> open --note "فشل الـ Retest: <ما حدث>"` — وحلل هل الإصلاح كان جزئيا أم كسره تغيير آخر

## أولوية الاختبار
1. كل الـ blockers
2. البنود التي شاركت جذرا واحدا — **إصلاح جذر واحد قد يكسر تابعا لم يُختبر**
3. البنود المتناقضة (`--conflicts`)
4. الباقي

## اختم بـ
- جدول: البند | الحالة قبل | نتيجة الـ Retest | الدليل
- أي Regression ظهر في بند كان يعمل
- الحكم: GO / NO-GO مع سبب محدد
