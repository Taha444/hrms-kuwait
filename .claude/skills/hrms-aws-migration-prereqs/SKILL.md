# متطلبات النقل إلى AWS

هذان البندان **يجب حلهما قبل النقل** — لا بعده. تأجيلهما يعني فقد ملفات أو تنفيذ مزدوج على بيانات حقيقية.

## 1. `./uploads` → تخزين دائم

### لماذا
مجلد على قرص السيرفر يعني:
- **إعادة نشر أو استبدال instance = ضياع كل المستندات**
- تعدد النسخ = الملف مرفوع على واحدة والباقي لا تراه
- لا نسخ احتياطي مستقل عن السيرفر

النظام يحمل **جوازات وبطاقات مدنية وعقود وإقامات**. ضياعها ليس عطلا تقنيا فقط.

### الحل
S3 مع:
- Bucket خاص · **Block Public Access مفعّل**
- التطبيق يصل بـ **IAM role على الـ EC2** — لا مفاتيح مكتوبة في ملف
- Encryption at rest
- Versioning على الـ bucket — طبقة حماية إضافية غير طبقة الإصدارات في التطبيق
- العرض للمستخدم بـ **presigned URLs محدودة المدة** — يطابق قاعدة «عدم عرض Storage URL أو File Path للمستخدم»

### الترحيل
```
1. ارفع الملفات الحالية إلى S3 مع الحفاظ على البنية
2. تحقق من العدد والبصمات: كل ملف في القاعدة له مقابل في S3
3. حوّل التطبيق للقراءة من S3
4. اختبر: رفع · تنزيل · معاينة · مستند قديم · مستند جديد
5. لا تحذف المجلد القديم قبل التحقق الكامل والنسخ الاحتياطي
```

استعلام التحقق:
```sql
-- ملفات في القاعدة بلا مقابل في التخزين
SELECT id, storage_key FROM document_artifacts WHERE storage_key IS NOT NULL;
-- قارن النتيجة بمحتوى الـ bucket
```

### مسارات تُنسى
لا تنقل مجلد الرفع الرئيسي فقط. ابحث عن كل موضع يكتب على القرص:
```
مرفقات الطلبات · صور التواقيع · المستندات المولّدة · التصديرات المؤقتة
لوجو الشركة · مرفقات التجديد · نسخ العقود الثلاث
```

## 2. المهام المجدولة والتشغيل المزدوج

### لماذا
مع أكثر من instance، الـ scheduler يعمل على كل واحدة. النتيجة:
- **الفحص اليومي يُنشئ تنبيهات ومهام مكررة**
- إشعارات مزدوجة
- في الأسوأ: قيود مالية مكررة

هذا يفاقم بلاغا قائما بالفعل عن مهام مكررة و SLA/digest duplicates.

### الحلول — بالترتيب
| الحل | متى |
|---|---|
| **قفل موزّع** على مستوى القاعدة أو Redis قبل تنفيذ أي job | الأبسط والأسرع |
| **EventBridge + Lambda أو ECS task** تستدعي endpoint محمي | الأنظف على AWS |
| instance واحدة معلّمة كـ scheduler | يعمل لكنه هش |

**بأي حل: أضف idempotency على مستوى الـ job نفسه.** القفل قد يفشل، والـ job يجب أن يكون آمنا لو عمل مرتين.

مفتاح idempotency للفحص اليومي:
```
(document_id, alert_window, date)
```
والنافذة هي 90 أو 30 أو التذكير المتكرر.

### اختبار
```
شغّل الـ job مرتين يدويا       → لا تكرار
شغّله متزامنا على نسختين       → لا تكرار
أوقف نسخة أثناء التنفيذ        → لا فقد ولا قفل عالق
```

### الـ jobs التي تحتاج الحماية
```
فحص تواريخ الانتهاء اليومي · إشعارات SLA · Digest
تذكيرات التجديد · إغلاق المهام التلقائي · أي job على Payroll
```

## بندان مرتبطان لا تنسهما أثناء النقل
- **ضبط NTP على الخادم من أول يوم.** عطل الـ 2FA الموثق كان فرق 111 ثانية في ساعة السيرفر.
- **الأسرار في Secrets Manager أو Parameter Store** لا في `.env` على القرص. `/.env` مكشوفا أول ما يجربه أي فاحص.

## البنود
`AWS-01` — الرفع على تخزين دائم بلا مفاتيح مكتوبة وبلا Storage URL مكشوف
`AWS-02` — المهام المجدولة لا تعمل أكثر من مرة مع تعدد النسخ
