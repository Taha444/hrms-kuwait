# من تنبيه إلى معاملة — إصلاح العطل الحالي

## الأعراض الموثقة
شاشة «معاملات المندوب › معاملات تجديد الإقامة»، شركة الاتحاد الخليجي للأقمشة:
- اللوحة اليمنى: **«لا توجد معاملات تجديد»**
- تحتها: **«تستحق التجديد ولم يُفتح لها ملف (1)»** وفيها بطاقة `QA-RES-0002` بتاريخ `2026-08-28` و«6 يوم متبقي»
- اللوحة اليسرى: **«اختر معاملة لعرض تفاصيلها»** — وتبقى كذلك بعد الضغط
- **لا يوجد زر «بدء معاملة التجديد»** في أي مكان

## التشخيص الأولي
العنوانان في الشاشة يكشفان البنية: النظام يعرض **مجموعتين مختلفتي المصدر**:
1. `معاملات تجديد` = سجلات `renewal_case` حقيقية → فارغة
2. `تستحق التجديد ولم يُفتح لها ملف` = **تنبيهات محسوبة** من `expiry_date` → فيها عنصر واحد

البطاقة في المجموعة الثانية **ليس لها `case_id`**، فالضغط عليها لا يجد شيئا يفتحه، ولوحة التفاصيل تبقى فارغة بصمت.

هذا هو التشخيص الأرجح — **تحقق منه قبل الإصلاح** ولا تفترضه.

## خطوات التشخيص — بهذا الترتيب
### 1. افحص الشبكة عند الضغط
افتح Network tab واضغط البطاقة:
- **لا طلب يُرسل أصلا** → لا `onClick` على بطاقات هذه المجموعة (الأرجح)
- **طلب يُرسل ويرجع 404** → الراوت موجود لكن `case_id` فارغ أو غير موجود
- **طلب يرجع 403** → مشكلة صلاحيات، وليست ربط واجهة
- **طلب يرجع 200 بجسم فارغ** → الـ endpoint يستعلم عن `renewal_case` غير موجود

### 2. افحص مصدر كل مجموعة
```
من أين تأتي «معاملات تجديد»؟           → جدول renewal_cases غالبا
من أين تأتي «تستحق ولم يُفتح لها ملف»؟  → استعلام محسوب على employee_documents
هل النوعان يمران على نفس المكوّن في الواجهة؟
هل البطاقة في المجموعة الثانية تحمل id أصلا؟
```

### 3. ابحث عن إجراء البدء
```
هل يوجد endpoint لإنشاء renewal_case؟ (POST /api/renewals أو ما يشبهه)
هل يوجد زر في الواجهة يستدعيه؟
هل الزر مخفي بشرط دور؟
```
**انتبه للقطة**: الحساب الظاهر `Super Admin` وهو يتصفح شاشة المندوب. لو إجراء البدء مقيّد بدور PRO فقط، فقد يكون الزر مخفيا لسبب صلاحيات لا لسبب برمجي. **اختبر بحساب PRO حقيقي قبل الحكم.**

### 4. سجّل النتيجة قبل الإصلاح
اكتب: أي الاحتمالات الأربعة تحقق، وبأي دليل. لا تصلح على أساس تخمين.

## الإصلاح المطلوب

### أ. البطاقة تفتح دائما
كل بطاقة في الشاشتين تفتح شاشة تفصيل — لكن بمحتوى مختلف حسب النوع:

**تنبيه بلا معاملة** → لوحة تفصيل تعرض:
```
اسم الموظف · الشركة · الفرع · رقم الإقامة الحالية
تاريخ الانتهاء · الأيام المتبقية · المندوب المسؤول
[زر أساسي: بدء معاملة التجديد]
```

**معاملة قائمة** → لوحة المعاملة الكاملة بمراحلها و Timeline وإجراءاتها.

**ممنوع التجاهل الصامت.** لو لم يُفتح شيء لأي سبب (صلاحية، بيانات ناقصة)، تظهر رسالة تشرح السبب.

### ب. إجراء «بدء معاملة التجديد»
```
POST /api/renewals   { document_id, employee_id, company_id }
```
ينشئ `renewal_case` بـ:
```
case_no · employee_id · company_id · branch_id · assigned_pro_id
current_document_id · current_expiry_date · started_at
status = RENEWAL_STARTED · started_by
```
ثم:
- التنبيه يختفي من مجموعة «لم يُفتح لها ملف»
- المعاملة تظهر في «معاملات تجديد»
- Timeline يبدأ بحدثين: `Expiry Detected` ثم `Renewal Started by PRO`

**Idempotency إلزامية:** ضغط الزر مرتين ينشئ معاملة واحدة. القيد:
```sql
UNIQUE (current_document_id) WHERE status NOT IN ('COMPLETED','CANCELLED')
```

### ج. من يملك حق البدء
- **PRO المسند للشركة** — الأساس
- **HR** ضمن شركته — مسموح (المواصفة تنص أن النظام أو HR قد ينشئ الحالة)
- **Super Admin** — للإعداد والاختبار، مع تسجيل واضح في Timeline
- الأزرار تُبنى من استجابة الخادم لا من منطق في الواجهة

### د. نافذة التجديد
- **الطبيعي**: 30 يوما أو أقل → المسار المختصر
- **المبكر**: 31–90 يوما أو بسبب خاص → يمر بـ Manager و HR قبل المندوب
- الحد يُقرأ من `policy_rule` (`early_renewal_days`) **لا من رقم مكتوب في الكود**

الحالة في اللقطة: 6 أيام متبقية → **تجديد طبيعي عاجل**.

## توحيد مصدر البيانات
العطل المتكرر في هذا النظام: كل شاشة تستعلم بنفسها. المطلوب **مصدر واحد** يغذّي:
```
Renewals · Operations Center · PRO Dashboard · Alerts/Notifications · Expiry Engine
```
اختبار التحقق: أنشئ إقامة تنتهي خلال 14 يوما، ثم افتح الأربع شاشات — **يجب أن تعرض نفس العدد ونفس الحالة ونفس التاريخ**.

اللقطة الحالية تُظهر إقامة واحدة مستحقة؛ تأكد أن مركز العمليات ولوحة المندوب يعرضانها أيضا وبنفس البيانات.

## الفحص اليومي — منع التكرار
```
مهمة Active واحدة لكل مستند
تشغيل Daily Scan مرتين لا ينشئ تكرارا
```
التنفيذ: مفتاح idempotency على `(document_id, alert_window)` — والنافذة هي 90 أو 30 أو التذكير المتكرر.

التنبيهات: **قبل 90 يوما · قبل 30 يوما · تذكيرات متكررة بعدها حتى الإتمام.**

## البيانات المعروضة في البطاقة
المواصفة تطلب صراحة: **اسم الموظف · الشركة · الفرع · تاريخ الانتهاء · الأيام المتبقية · حالة التجديد**.

البطاقة الحالية تعرض `QA Renewal Window` و `QA-RES-0002` و التاريخ والأيام — **اسم الموظف والفرع ناقصان**، وما يظهر كاسم هو على الأرجح وصف المستند لا اسم الموظف. أضفهما.
