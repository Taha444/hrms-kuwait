# HRMS Security Preflight

## نطاق هذا السكيل
فحص أمني تشغيلي قبل التسليم — **وليس اختبار اختراق كامل**. لو النظام سيحمل بيانات موظفين حقيقية لشركة، انصح العميل صراحة بفحص أمني مستقل من طرف ثالث. هذا السكيل يغطي الأساسيات التي يجب ألا تمر.

## 1. الصلاحيات والعزل
```bash
source .claude/hrms/scripts/env.sh
bash .claude/hrms/scripts/rbac-probe.sh
```
- [ ] لا `200` لدور غير مخوّل في أي endpoint حساس
- [ ] المنع في **UI و API و Storage endpoint** — الثلاثة، لا واحدا
- [ ] الرد المرفوض **لا يسرّب بيانات في جسمه** (لا أسماء ولا أرقام ولا رسائل تكشف البنية)
- [ ] الرابط المباشر لأي action يرد 403 لغير المعيّن
- [ ] `stale task` (بعد انتقال المرحلة) مرفوض
- [ ] `self-approval` مرفوض على الخادم
- [ ] **العزل بين الشركات**: مستخدم GUF لا يصل لأي سجل في MUF — جرّب بتغيير الـ ID في الرابط والـ API
- [ ] `IDOR`: غيّر `/api/employees/1` إلى `/2` و `/999` — هل يرد بيانات موظف خارج نطاقك؟

**اختبار IDOR إلزامي.** هو أكثر ثغرة شائعة في أنظمة متعددة الشركات، ولا تكشفه مصفوفة الأدوار وحدها.

## 2. المصادقة والجلسات
- [ ] كل كلمات السر التجريبية **معطّلة** — جرّب كل ما تعرفه منها
- [ ] لا حساب إداري مشترك — حسابات شخصية فقط
- [ ] إجبار تغيير كلمة السر عند أول دخول
- [ ] لا بيانات دخول ظاهرة في أي شاشة أو Export أو Log أو كود المصدر
- [ ] `Rate limit` و `Lockout` على محاولات الدخول — جرّب 10 محاولات خاطئة
- [ ] المستخدم المعطّل لا يدخل (**هذه نجحت سابقا — تأكد أنها لم تنكسر**)
- [ ] إنهاء الجلسات القديمة بعد تغيير كلمة السر أو تعطيل الحساب
- [ ] **2FA يعمل فعليا** عند الدخول لا كصفحة إعداد — تحقق من `NTP sync` أولا، فالعطل الموثق كان فرق 111 ثانية
- [ ] `Auto Logout` بعد ~10 دقائق خمول للأدوار الحساسة
- [ ] التوكن: مدة صلاحية معقولة · لا يُخزَّن في `localStorage` إن أمكن · `HttpOnly` و `Secure` و `SameSite` للكوكيز

## 3. الملفات والتخزين
- [ ] رابط ملف مباشر بلا توكن → **مرفوض**
- [ ] لا `Storage URL` ولا مسار ملف معروض للمستخدم في أي استجابة
- [ ] رفع ملف: التحقق من النوع والحجم **على الخادم** لا في الواجهة
- [ ] رفع ملف بامتداد مزدوج أو `.php`/`.svg` بمحتوى نشط → مرفوض
- [ ] المستندات الحساسة (تظلم، إنذار، EOS) لا تظهر في بحث عام
- [ ] صفحة التحقق بالـ QR لا تعرض الراتب ولا IBAN ولا تفاصيل التحقيق

## 4. النقل والترويسات
- [ ] HTTPS إجباري · إعادة توجيه HTTP → HTTPS
- [ ] الشهادة صالحة وغير منتهية · تنبيه قبل انتهائها
- [ ] `HSTS` · `X-Content-Type-Options: nosniff` · `X-Frame-Options` أو `frame-ancestors` · `Referrer-Policy`
- [ ] `Content-Security-Policy` موجودة ولو أساسية
- [ ] لا `Server` ولا `X-Powered-By` يكشفان الإصدار
- [ ] CORS مضبوط على النطاقات المطلوبة فقط — لا `*`

## 5. التسريب والمسارات المكشوفة
جرّب مباشرة:
```
/.env · /.git/config · /api/config · /actuator · /debug · /swagger · /api-docs
/backup · /dump.sql · /phpinfo.php · /admin
```
- [ ] كلها ترد 404 أو 403 — أي `200` = **blocker**
- [ ] صفحات الخطأ لا تعرض `stack trace` ولا مسارات الخادم ولا استعلامات SQL
- [ ] لوجات النظام لا تحتوي كلمات سر ولا توكنات ولا أرقام مدنية كاملة

## 6. التصدير والخصوصية
- [ ] `Masking` حسب الدور في كل تصدير
- [ ] IBAN مقنّع في الإيصال العام، كامل لصلاحية محددة فقط
- [ ] الرقم المدني لا يظهر كاملا في مستند عام
- [ ] الموظف لا يرى تواريخ إجازته في أي طبقة (الحجب في استجابة الخادم لا في CSS)
- [ ] `Export Audit` مسجّل مع سبب للتصدير الحساس

## 7. الحقن والمدخلات
- [ ] SQL: جرّب `' OR '1'='1` و `'; --` في حقول البحث والفلاتر
- [ ] XSS: أدخل `<img src=x onerror=alert(1)>` في حقول النص وشاهد أين تُعرض — بالذات في تفاصيل الطلب والمستندات
- [ ] قوالب المستندات: **تعقيم HTML** · لا Scripts ولا Events ولا Active SVG
- [ ] لا `Session Token` يُمرَّر للطباعة أو في رابط
- [ ] معاملات الرابط: لا بيانات شخصية في `query string`

## 8. قبل الإتاحة للعميل
- [ ] `Reset Demo Data` وأدوات الاختبار **معطّلة**
- [ ] بيانات QA منظّفة أو معزولة
- [ ] مفاتيح Kiosk **مُدوَّرة** وغير معروضة كاملة
- [ ] Staging منفصلة تماما عن نسخة العميل
- [ ] لا يظهر `Development` على رابط التسليم
- [ ] حساب Super Admin الداخلي **لا يُسلَّم**

## نموذج التقرير
لكل بند فاشل:
```
البند · الخطورة · ما جربته بالضبط · النتيجة · الأثر على العميل · الإصلاح المقترح
```
**لا تكتب "آمن" لبند لم تجربه.** اكتب "لم يُختبر" والسبب.

## حدود هذا الفحص — قلها للعميل
هذا فحص تشغيلي أساسي. **لا يغطي**: مراجعة كود أمنية معمّقة · اختبار اختراق بأدوات متخصصة · فحص المكتبات والاعتماديات · تحليل تهديدات معماري · امتثال لمعيار محدد.
لو النظام سيحمل بيانات موظفين حقيقية، فحص مستقل من طرف ثالث توصية مهنية لا رفاهية.
