# HRMS PRO · Residency · Archive (عنقود PRO — 10 بنود، 4 منها blocker)

## الجذر الواضح
Dashboard تقول «الإقامات السارية = 0»، ومركز العمليات يعرض 4 حالات حرجة، وصفحة Renewals فارغة و `/api/renewals` يرجع `[]` — **ثلاث شاشات بثلاثة استعلامات مختلفة على نفس البيانات**.

**ابدأ بتوحيد مصدر البيانات، ثم أصلح الشاشات.** إصلاح كل شاشة على حدة سيعيد التناقض.

## 1. OCR — `PRO-01` (blocker)
العطل الموثق: رُفع مستند إقامة واضح فيه تاريخ انتهاء. الـ OCR قرأ النص لكن رجع `confidence = 0.0` و `MRZ incomplete` وبلا `Expiry Date`.

**نقطة متفق عليها مسبقا: الـ OCR شغّال — فالمستخدم لا يُطالب بإدخال تواريخ الانتهاء يدويا.**

المسار المطلوب:
```
رفع المستند → OCR يقرأ البيانات وتاريخ الانتهاء
→ التاريخ يُحفظ على المستند/الإقامة → Dashboard تتحدث
→ مركز العمليات يشوف المستند → يظهر في التجديدات عند دخول الفترة
→ التنبيه يتولد حسب تاريخ الانتهاء
```
- إن كانت الثقة منخفضة: **اطلب تأكيد المستخدم** بدل الفشل الصامت.
- المستخدم يقدر يصحح القراءة.
- ينطبق على: الإقامة، إذن العمل، الجواز، البطاقة المدنية، ومستندات الشركة ذات تاريخ الانتهاء.

## 2. صفحة التجديدات — `PRO-02` `PRO-04` (blocker)
- الصفحة فارغة و `/api/renewals` يرجع `[]` رغم وجود إقامة تنتهي خلال 14 يوما اكتُشفت كحالة حرجة في مركز العمليات.
- **لا يوجد Start/Create Renewal Action** أصلا.

المسار الكامل المطلوب تنفيذه واختباره على حالة QA واحدة على الأقل:
```
Alert → Start Renewal → Required Documents → Under Renewal
→ Government Reference → Fees/Receipt عند الحاجة
→ New Number/Expiry → HR Verification → Employee Notification
→ Task Closure → Archive Current/History → Audit
```
مراحل إضافية من المواصفة: Contracts/Signature Stage · Work Permit · Civil ID · Timeline.

## 3. فصل المسارين — `PRO-10`
- **التجديد المبكر** (31-90 يوما أو سبب خاص): `Employee → Manager → HR → PRO → Government Process → Verification → Update Document → Completed`
- **التجديد الطبيعي** (30 يوما أو أقل): المسار المختصر المعتمد.

## 4. إزالة الصفحة القديمة — `PRO-05`
**القرار النهائي: صفحة PRO Transactions القديمة تُحذف. لا تُصلح ولا يُعاد بناؤها.**
- صفحة Residency Renewals الجديدة هي المسار **الوحيد** للإقامة.
- مستندات وتراخيص الشركة والفروع تُدار من **Company Archive** و **Branch Archive** فقط.

## 5. الإشعارات ومنع التكرار — `PRO-06`
- قبل **90 يوما** · قبل **30 يوما** · تذكيرات متكررة بعدها حتى الإتمام.
- **مهمة Active واحدة لكل مستند** — لا أكثر.
- تشغيل Daily Scan أكثر من مرة **لا ينشئ تكرارا** (idempotency على مفتاح المستند + النافذة).
- بعد التجديد: الجديدة `Current` والقديمة `History` · المهمة تُغلق · التذكيرات تتوقف · Audit Before/After.

## 6. العدادات المتناقضة — `PRO-03` `PRO-07` `PRO-08`
| البلاغ | التناقض |
|---|---|
| `PRO-03` | Dashboard: الإقامات السارية = 0 في الشركتين رغم وجود مستندات مرفوعة |
| `PRO-07` | Dashboard: 2 أو 3 مهام حكومية · الفلتر: 0 |
| `PRO-08` | Dashboard: 76% تراخيص سارية · مركز العمليات: لا تراخيص منتهية أو قريبة |

**الثلاثة نفس الجذر.** أصلح الاستعلام المشترك مرة واحدة، ثم تحقق من الثلاثة معا.

## 7. حقول مستندات الأرشيف — `PRO-09`
```
Document Type · Number · Issue Date · Expiry Date · Issuing Authority
Company · Branch · Assigned PRO · Attachment · Notes · Status · Version History
```

## 8. نطاق المندوب
- يرى الشركات والفروع **المسندة له فقط**.
- لا يرى بيانات شركات أخرى.
- لا يرى الرواتب ولا بيانات HR غير المطلوبة (مرتبط بـ `ACCESS-04`).
- صفحة الروابط الحكومية لـ PRO فقط (`ACCESS-05` — **تحقق أولا، المصدر متناقض**).
- المندوب **لا يدخل في الاستئذان أثناء الدوام**، ولا ينفّذ إذن خروج إلا للسفر (مرتبط بـ `WF-03`).

## 9. منع انتحال المستند الحكومي
النظام **لا يولّد** إقامة ولا بطاقة مدنية ولا إذن عمل بشعار حكومي. يولّد **غلاف متابعة شركة فقط**، ويحفظ المستند الحقيقي الصادر من PAM/MOI/PACI مع مرجعه وتاريخه وبصمته ومن تحقق منه.

## التحقق
اختبر على **GUF و MUF معا** — بلاغات هذا العنقود ذكرت الشركتين صراحة.
