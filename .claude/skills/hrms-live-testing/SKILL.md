# HRMS Live Testing — التشغيل والقيادة

## قبل أي شيء: أربعة أسئلة إجبارية
لا تبدأ اختبارا قبل معرفة الإجابات. اسألها مرة واحدة في بداية الجلسة:

1. **الرابط والبيئة** — ما رابط النسخة؟ هل هي Staging أم النسخة التي سيستخدمها العميل؟
2. **الحسابات** — ما حسابات الاختبار المتاحة لكل دور؟ (Employee, Branch Supervisor, Manager, HR, Accountant, PRO, Owner, Super Admin)
3. **البيانات** — هل الاختبار على بيانات Demo أم بيانات حقيقية؟
4. **الأداة** — هل Playwright مثبت؟ هل يوجد متصفح MCP متصل؟ أم نختبر عبر الـ API فقط؟

## قاعدة السلامة الأولى
```
اختبار كتابة على بيانات حقيقية = ممنوع
```
- عمليات القراءة والفتح: مسموحة في أي بيئة.
- عمليات الكتابة (إنشاء طلب، اعتماد، تشغيل راتب، رفع مستند، تعديل موظف): **Staging أو بيانات Demo فقط**.
- إن كانت البيئة الوحيدة المتاحة هي نسخة العميل: نفّذ القراءة والفحص الأمني فقط، وقل صراحة أي اختبارات لم تُنفَّذ ولماذا.
- **ممنوع نهائيا**: تشغيل Payroll Finalize · إنهاء خدمة موظف · حذف أي سجل · تعديل صلاحيات حساب حقيقي — على أي بيئة، إلا بطلب صريح ومحدد.

## اختيار الأداة
افحص المتاح بالترتيب:

### 1. Playwright (الأفضل للاختبار المتكرر)
```bash
npx playwright --version 2>/dev/null || npm i -D @playwright/test && npx playwright install chromium
```
المزايا: تكرار آلي · لقطات شاشة · تسجيل الشبكة · اختبار متوازٍ للأدوار.
اكتب الاختبارات في `tests/e2e/` واحفظها — هي جزء من التسليم، وليست شغلا مؤقتا.

قالب أساسي:
```js
// tests/e2e/_helpers.js
export async function loginAs(page, role) {
  const u = process.env[`HRMS_${role}_USER`], p = process.env[`HRMS_${role}_PASS`];
  await page.goto(process.env.HRMS_BASE_URL + '/login');
  await page.fill('[name=username]', u);
  await page.fill('[name=password]', p);
  await page.click('button[type=submit]');
  await page.waitForURL(/dashboard|home/);
}
```
**الحسابات من متغيرات بيئة فقط — ممنوع كتابتها في الكود أو في أي ملف يُرفع للريبو.**

### 2. متصفح MCP (للاستكشاف اليدوي)
مناسب لأول جولة استكشافية وللأشياء البصرية (تداخل، قص، RTL). أبطأ وأقل قابلية للتكرار.
استخدمه للاستكشاف، ثم حوّل ما اكتشفته إلى اختبار Playwright.

### 3. curl / HTTPie (للـ API وللفحص الأمني)
**لا غنى عنه** — كثير من عيوب هذا النظام لا تظهر إلا بضرب الـ API مباشرة:
```bash
# احصل على التوكن
TOKEN=$(curl -s -X POST "$BASE/api/auth/login" \
  -H 'Content-Type: application/json' \
  -d "{\"username\":\"$U\",\"password\":\"$P\"}" | jq -r .token)

# اضرب endpoint وسجّل الكود والجسم
curl -s -o /tmp/body.json -w '%{http_code}\n' \
  -H "Authorization: Bearer $TOKEN" "$BASE/api/employees"
```

## قواعد الاختبار

### اختبر بالطبقات الثلاث دائما
| الطبقة | السؤال |
|---|---|
| **الواجهة** | هل الزر/الرابط/الحقل ظاهر؟ |
| **الـ API** | هل الخادم يسمح فعلا؟ اضربه مباشرة بلا واجهة |
| **الأثر** | هل تغيّر السجل في قاعدة البيانات فعلا؟ |

عطل واحد قد يظهر في طبقة ويختفي في أخرى. **إخفاء الزر ليس منعا.**

### اختبر الشركتين
`GUF` و `MUF`. البلاغات تثبت أن نفس الـ endpoint يعمل على واحدة ويفشل على الأخرى.
أي نتيجة على شركة واحدة = **اختبار غير مكتمل**.

### اختبر اللغتين
عربي RTL وإنجليزي LTR — النصوص والأرقام والتواريخ والعملة والقص والتداخل.

### التقط الأدلة أثناء الاختبار لا بعده
لكل نتيجة: كود الحالة · جسم الرد (منقّى من الأسرار) · لقطة شاشة عند الأعطال البصرية · وقت التنفيذ · الحساب والشركة.
احفظها في `.claude/hrms/evidence/<run-id>/`.

## الأداة المرافقة
```bash
python3 .claude/hrms/scripts/testrun.py --new "جولة أولى"     # ابدأ جولة
python3 .claude/hrms/scripts/testrun.py --list                # الرحلات المتاحة
python3 .claude/hrms/scripts/testrun.py --result JRN-01 pass --note "..."
python3 .claude/hrms/scripts/testrun.py --summary             # ملخص الجولة
bash .claude/hrms/scripts/smoke.sh                            # فحص سريع للأساسيات
bash .claude/hrms/scripts/rbac-probe.sh                       # مصفوفة دور × endpoint
```

## ترتيب الجلسة الموصى به
```
1. smoke.sh                  ← هل النظام حي أصلا؟ هل الـ endpoints الأساسية ترد؟
2. تسجيل دخول بكل دور        ← أي دور لا يدخل يوقف اختباره
3. rbac-probe.sh             ← مصفوفة الصلاحيات، أسرع طريقة لكشف الثغرات
4. الرحلات حسب الدور         ← من سكيل hrms-test-journeys
5. فحوص سلامة البيانات       ← من سكيل hrms-data-integrity
6. الفحص الأمني              ← من سكيل hrms-security-preflight
```

## ما لا تفعله
- لا تفترض أن الشاشة تعمل لأنها حمّلت — تحقق من البيانات فيها.
- لا تعتبر `200` نجاحا — اقرأ الجسم. كثير من الأنظمة ترجع 200 مع `[]` أو رسالة خطأ.
- لا تسجّل نتيجة بلا دليل.
- لا تصلح شيئا أثناء الاختبار — سجّل واستمر، ثم أصلح بعد اكتمال الجولة. الإصلاح أثناء الاختبار يفسد خط الأساس.
- لا تكتب كلمات السر في أي ملف أو لوج أو تقرير.
