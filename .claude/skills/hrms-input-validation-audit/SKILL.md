# مراجعة التحقق من المدخلات

## القاعدة
**الواجهة ليست طبقة التحقق.** كل قاعدة في الواجهة يجب أن يكون لها مقابل على الخادم، لأن الطلب قد يصل من `curl` مباشرة.

طريقة الاختبار: **تجاوز الواجهة دائما** واضرب الـ API مباشرة.

## 1. الحقول الإلزامية
لكل endpoint كتابة:
```bash
curl -X POST "$B/api/employees" -H "Authorization: Bearer $T" \
  -H 'Content-Type: application/json' -d '{}'                    # فارغ
curl -X POST ... -d '{"full_name":"x"}'                          # جزئي
curl -X POST ... -d '{"full_name":null,"civil_id":null}'         # قيم null
```
المتوقع: `422` أو `400` **يسمّي الحقل الناقص**، ولا يُنشأ أي سجل.

**فحص إضافي مهم:** بعد الطلب الفاشل، هل نشأ سجل جزئي؟ أو User؟ أو Task؟ أو Audit نجاح؟
البلاغ الموثق ينص: «الموظف غير الصالح لا ينشئ أي سجل، ولا User ولا Task ولا Audit نجاح».

## 2. الكتابة الجماعية — Mass Assignment
أرسل حقولا لا يملكها المستخدم:
```bash
curl -X POST "$B/api/requests" -H "Authorization: Bearer $EMPLOYEE_T" -d '{
  "type":"leave","start_date":"2026-09-01",
  "status":"approved",              ← تخطي المسار
  "company_id":99,                  ← تخطي النطاق
  "employee_id":11,                 ← انتحال موظف آخر
  "id":1, "created_at":"2020-01-01" ← تلاعب بالمفاتيح
}'
```
المتوقع: تُتجاهل كلها أو تُرفض. **قبول أي منها = `critical`.**

كرر على: تعديل موظف · تحديث حساب بنكي · إنشاء مستخدم · انتقال مرحلة.

## 3. الحقن
```
SQL     '  OR '1'='1  ;--  ' UNION SELECT NULL--
        في: البحث · الفلاتر · الترتيب (`sort=`) · ترقيم الصفحات
XSS     <img src=x onerror=alert(1)>  في حقول تُعرض في تفاصيل الطلب والمستندات
مسارات  ../../etc/passwd  في أسماء الملفات ومعرّفات المستندات
قوالب   {{7*7}}  ${7*7}  في أي حقل يدخل قالب PDF
```
**`sort` و `order_by` تحديدا** ثغرة شائعة لأنها تُدمج في الاستعلام كنص غالبا.

**حقن القوالب خطر خاص هنا** — النظام يولّد PDF من قوالب. القاعدة: التوليد Server-side من قائمة حقول مسموحة، بلا HTML أو JS حر.

## 4. الأنواع والحدود
```
نص مكان رقم        {"amount":"abc"}
سالب مكان موجب     {"amount":-500}  {"days":-5}
صفر                {"salary":0}      ← EOS يجب أن يرفضه
كبير جدا           {"amount":999999999999}
عشري مكان صحيح     {"days":2.7}
تاريخ غير صالح     "2026-13-45"  "not-a-date"
تاريخ منطقيا خاطئ  نهاية قبل بداية · انتهاء خدمة قبل التعيين
نص طويل جدا        10000 حرف في حقل اسم
مصفوفة مكان نص     {"name":["a","b"]}
كائن مكان مصفوفة   {"ids":{"a":1}}
يونيكود وrtl       أسماء عربية · محارف تحكم اتجاه
```

**قواعد أعمال موثقة يجب اختبارها:**
- `salary <= 0` مرفوض في EOS
- `End Date` قبل `Hire Date` مرفوض
- غياب قبل تاريخ التعيين مرفوض
- السجل التجاري فريد — والتحقق **في القاعدة** لا في الكود فقط

## 5. التفرّد والتزامن
```bash
# أرسل نفس الطلب مرتين متزامنتين
for i in 1 2; do curl -X POST "$B/api/companies" -d '{"cr":"12345"}' & done; wait
```
المتوقع: واحد ينجح والآخر يُرفض. **نجاح الاثنين يعني القيد في الكود لا في القاعدة.**

كرر على: إنشاء شركة بنفس السجل · موظف بنفس المدني · معاملة تجديد لنفس المستند · Payroll run لنفس الشركة والفترة.

## 6. Idempotency
```bash
# اضغط Complete مرتين
curl -X POST "$B/api/tasks/5/complete" -H "..." &
curl -X POST "$B/api/tasks/5/complete" -H "..." &
wait
```
المتوقع: **أثر واحد وسجل تدقيق واحد**.

## التسجيل
كل قبول لمدخل يجب رفضه = نتيجة. الخطورة:
- Mass assignment يغيّر حالة أو نطاق → `critical`
- حقن ناجح → `critical`
- قيد تفرّد مخترق بالتزامن → `high`
- نوع خاطئ يُقبل بلا أثر → `medium`
