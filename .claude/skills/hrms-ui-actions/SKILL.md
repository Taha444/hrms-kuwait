# HRMS UI & Dynamic Action Bar (V2.2 §9، §29)

## 1. الشاشات الخمس
| الشاشة | المحتوى | القيد |
|---|---|---|
| `My Requests` | ما أنشأه المستخدم وحالته والخطوة الحالية | دون كشف بيانات غير لازمة |
| `My Actions` | **المهام التي يستطيع المستخدم التصرف فيها الآن فقط** | لا تعرض ما لا يملك فيه action |
| `Team Requests` | للمدير ضمن نطاقه | **قراءة لا تعني امتلاك قرار** |
| `Cases` | لـ HR/Finance/PRO حسب التخصص | كل جهة ترى تخصصها |
| `Workflow Monitor` | للمخوّلين للمتابعة | **بلا حق قرار تلقائي** |

## 2. شريط الإجراءات الديناميكي — القاعدة المركزية
**لا يوجد شريط موحّد باسم Approve/Reject.** الأفعال تُشتق من `task_instance.step.step_type` و `allowed_actions`:

```
DECISION         → Approve · Reject · Needs Info
VALIDATION       → Valid · Invalid · Return for Correction
EXECUTION        → Start · Complete · Cannot Complete
ACKNOWLEDGEMENT  → Acknowledge · Acknowledge with Comment · Dispute (إن سمحت السياسة)
CASE OWNER       → Assign · Convert · Escalate · Close
```

قواعد ملزمة:
- **كل رفض أو إعادة معلومات يحتاج سببا**؛ وبعض الأنواع تحتاج `reason_code` **ومرفقا**.
- **لا يُسمح بزر action لمستخدم غير المعيّن حتى لو فتح الرابط مباشرة** — والفحص على الخادم لا على الواجهة.
- الشريط يُبنى من استجابة الـ API (`allowed_actions` للمستخدم الحالي)، **لا من منطق مكتوب في الفرونت**.

## 3. عرض حالة الطلب
- **ممنوع** عرض حالة `Pending` بلا `current step` و `assignee` و `SLA`.
- `NEEDS_INFO` يظهر لمقدم الطلب كنموذج تعديل **على نفس الطلب وبنفس الرقم**، مع الحفاظ على Timeline كاملا.
- Timeline يعرض `current assignee` و `SLA` **دون كشف الحقول الحساسة** لمن لا يملك Field Permission.

## 4. أزرار المستند (§29)
| السياق | الزر الأساسي | الزر الثانوي |
|---|---|---|
| طلب تحت المراجعة | عرض الحالة / استكمال معلومات | طباعة سجل داخلي (Audit/HR فقط) |
| طلب مكتمل بوثيقة شركة | **تنزيل المستند الرسمي** | عرض سجل الطلب |
| طلب مكتمل بتحديث | **عرض نتيجة التنفيذ** | تنزيل إيصال إن وجد |
| معاملة حكومية مكتملة | **تنزيل المستند الحكومي** | تنزيل غلاف المتابعة |
| مستند موقّع | **تنزيل النسخة الموقّعة** | التحقق من الأصالة |

**لا يجوز أن يحمل الزران الملف نفسه.** المعاينة تحمل Watermark ولا تتيح Copy HTML نشط.

## 5. قائمة مراجعة قبل أي PR على الواجهة
- [ ] لا يوجد `<ApproveRejectBar />` عام في شاشة تفاصيل الطلب.
- [ ] الأزرار تأتي من `allowed_actions` في استجابة الخادم.
- [ ] كل حالة معروضة تحمل خطوة ومعيّنا و SLA.
- [ ] المستخدم غير المعيّن لا يرى أزرار action ولا يستطيع تنفيذها بالرابط المباشر.
- [ ] Employee لا يرى أنواعا داخلية ولا أكواد `request_type` خام.
- [ ] زر «تنزيل المستند الرسمي» منفصل عن «طباعة سجل الطلب».
- [ ] كل رفض يفتح حقل سبب إلزاميا.
