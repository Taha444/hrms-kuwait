# Package 10 — قنوات الإشعارات

## P10-33 — تفضيلات قد تكون كاذبة

### الوضع
التفضيلات تعرض `WhatsApp / SMS / Email` مفعّلة، بينما أغلب القوالب فعليا `in_app`.

### تحقّق أولا — بند `V-E`
> **لا نعتبر النقطة Bug قبل إثبات أن القناة غير موصولة فعلا.**

الفحص:
```
هل يوجد driver/integration لكل قناة في الكود؟
هل توجد مفاتيح مزوّد مضبوطة؟
هل يوجد سجل تسليم فعلي؟ (SELECT * FROM notification_deliveries WHERE channel <> 'in_app')
هل القوالب معرّفة لكل قناة أم in_app فقط؟
```

**أرسل إشعارا حقيقيا** عبر كل قناة مفعّلة وتتبّع وصوله. وجود الأيقونة أو الـ Toggle لا يعني التسليم.

### القرار
| النتيجة | الإجراء |
|---|---|
| **غير موصولة** | **لا تعرض Toggle يوحي بأن النظام سيرسل عبرها.** أخفِها أو علّمها "قريبا" بوضوح |
| **موصولة** | تحقق من `delivery / retry / failure state` |

**الخطر في عرض Toggle كاذب:** الموظف يفعّل واتساب ظنا أنه سيصله تنبيه انتهاء الإقامة، فلا يصله، فتنتهي إقامته. الوعد الكاذب أسوأ من غياب الميزة.

## لو موصولة — ما يجب التحقق منه
```
[ ] حالة التسليم تُسجَّل فعلا (sent/delivered/failed) من المزوّد لا من الافتراض
[ ] إعادة المحاولة عند الفشل المؤقت
[ ] حالة الفشل النهائي مرئية لا صامتة
[ ] تراجع للقناة البديلة عند فشل القناة الأساسية
[ ] لا بيانات حساسة في القناة الخارجية (راتب · رقم مدني · رقم إقامة)
[ ] الموافقة مسجّلة قبل الإرسال الخارجي
```

## القبول
`DOD-07` — والقاعدة: **ما يظهر للمستخدم كقناة متاحة يجب أن يعمل فعلا.**
