# محرك المهام — أربعة أعراض لجذر واحد

## الأعراض الموثقة
| العرَض | القياس الفعلي |
|---|---|
| مهام مكررة لنفس التجديد | `QA Renewal Window` ×3 · `QA Retest Aug14` ×2 |
| عداد المهام الحكومية | Dashboard **21** · الفلتر **7** |
| تراكم عناصر HR | **44** مفتوح = 6 مهام + 38 إشعار/Digest/SLA |
| اسم المهمة | «طلب **طلب** إجازة» |

## الجذر المشترك
**لا يوجد تعريف واضح لما هو «مهمة».** كل شيء يُكتب في نفس الجدول ويُعدّ في نفس العداد.

**رتّبها معا لا واحدة واحدة.** إصلاح العداد وحده يعطي رقما مضبوطا على بيانات مكررة.

## 1. التعريف أولا — قبل أي كود
```
Task         = مطلوب من هذا المستخدم إجراء الآن، وله زر يغيّر حالة شيء
Notification = معلومة. لا إجراء. لا تُعدّ في صندوق المهام
Digest       = تجميع دوري. إشعار واحد لا عشرات
SLA Reminder = تذكير بمهمة قائمة — لا مهمة جديدة
```

اختبار الفصل: **لو لم يفعل المستخدم شيئا، هل يتعطل عمل؟** نعم = مهمة. لا = إشعار.

بهذا المعيار، 38 من 44 عنصر عند HR **ليست مهاما**.

## 2. منع التكرار
مفتاح idempotency على مستوى إنشاء المهمة:
```
(entity_type, entity_id, step_code, assignee_id)  WHERE status = 'open'
```
**قيد فريد على مستوى قاعدة البيانات** — لا فحص في الكود فقط. الفحص في الكود يُخترق عند التزامن، وهذا بالضبط ما يحدث مع الـ scan المتكرر أو تعدد النسخ.

مصادر التكرار الثلاثة في هذا النظام:
- الفحص اليومي يعمل أكثر من مرة (مرتبط بمتطلبات AWS للمهام المجدولة)
- تغيير المرحلة ينشئ مهمة جديدة بلا إغلاق القديمة
- إعادة المحاولة بعد فشل جزئي

**الإغلاق التلقائي إلزامي:** عند تحرك المعاملة أو اكتمالها أو رفضها أو إلغائها، كل المهام المرتبطة بالخطوة السابقة تُغلق.

### احصر التكرار الحالي
```sql
SELECT entity_type, entity_id, step_code, assignee_id, COUNT(*)
FROM tasks WHERE status='open'
GROUP BY 1,2,3,4 HAVING COUNT(*) > 1;

-- مهام مفتوحة لمعاملات منتهية
SELECT t.id, t.entity_id, r.status FROM tasks t
JOIN renewal_cases r ON r.id = t.entity_id
WHERE t.status='open' AND r.status IN ('COMPLETED','CANCELLED');
```
نظّف القائم بـ migration مراجَعة **بعد** إضافة القيد، لا قبله.

## 3. العدادات
```
Government Tasks badge  ==  نتيجة Government filter بالضبط
```
نفس الاستعلام · نفس الفلتر · **نفس الـ company scope**.

القاعدة العامة: **أي عدّاد يُشتق من نفس الاستعلام الذي يغذّي القائمة التي يفتحها.** لا استعلام مستقل للعداد.

راجع كل العدادات لا هذا فقط — الظاهرة نفسها موثقة سابقا في عدادات التراخيص والإقامات.

اختبار: اضغط العداد → القائمة تفتح → **العدد المعروض = رقم العداد**. أي فرق = عطل.

## 4. الفصل في الواجهة
- صندوق المهام يعرض **الإجراءات المطلوبة فقط**
- الإشعارات في مكان منفصل بعدّاد منفصل
- Digest **إشعار واحد** لا عنصر لكل بند بداخله
- **SLA لنفس الحدث لا يتكرر عشرات المرات** — مفتاح `(event_id, reminder_window)` والتذكير يُحدَّث لا يُضاف

قبل الحذف: **صنّف ولا تمسح**. الإشعارات القديمة تنتقل لمكانها الصحيح، ولا تُحذف من التاريخ.

## 5. أسماء المهام
«طلب **طلب** إجازة» — القالب يضيف بادئة «طلب» والقيمة تحملها أصلا. **أزل إحداهما**، ولا تعالجها باستبدال نصي على المخرَج.

افحص كل قوالب أسماء المهام والإشعارات بحثا عن نفس النمط.

## التحقق
1. شغّل الفحص اليومي **مرتين متتاليتين** → لا مهمة إضافية
2. شغّله على نسختين متزامنتين → لا تكرار
3. حرّك معاملة مرحلة → المهمة القديمة أُغلقت والجديدة واحدة
4. أكمل معاملة → كل مهامها أُغلقت والعداد تغيّر **فورا**
5. العداد الحكومي = الفلتر الحكومي **بالرقم**
6. صندوق مهام HR: كم عنصر؟ كم منها يحتاج إجراء فعلا؟
7. Digest: عنصر واحد لا عشرات
8. SLA لحدث واحد: تذكير واحد يُحدَّث
9. لا «طلب طلب» في أي مكان
10. GUF و MUF
