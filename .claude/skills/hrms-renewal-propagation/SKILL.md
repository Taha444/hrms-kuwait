# نشر الأثر وإغلاق المعاملة

## المبدأ
المستندات النهائية **لا تظل محبوسة داخل المعاملة**. الأثر ينتشر إلى ملف الموظف والشاشات ومحرك التنبيهات، ثم تُغلق المعاملة.

## 1. حفظ المستندات في ملف الموظف
كل مستند يُحفظ تحت **نوعه الصحيح** في `Employee Documents`:
```
الإقامة الجديدة      → Residency
إذن العمل الجديد     → Work Permit
العقد الحكومي النهائي → Government Contract
البطاقة المدنية      → Civil ID
```
والربط بالمعاملة محفوظ في الاتجاهين.

## 2. الإصدارات — قاعدة صارمة
```
النسخة الجديدة  →  Current Version
النسخة القديمة  →  Previous Version / History
```
القديمة:
- **لا تُحذف**
- تبقى **قابلة للعرض**
- تبقى **قابلة للتنزيل**

الواجهة: **أحدث مستند على وش الصفحة**، مع مدخل واضح للنسخ السابقة.

هذا عطل موثق سابقا: النسخة الأحدث كانت تظهر صحيحة، لكن **لا يوجد زر للنسخ السابقة إطلاقا**. أضفه.

## 3. تطبيق تاريخ الانتهاء الجديد
بمجرد اعتماد التاريخ، يصبح **هو التاريخ المستخدم في النظام كله** وينعكس على:
```
Employee Profile · Renewals · Operations Center
PRO Dashboard · Expiry Engine · Alerts/Notifications
```

> **ولا يبقى جزء من النظام شايف التاريخ القديم وجزء آخر شايف الجديد.**

### كيف تضمن ذلك
لا تحدّث كل شاشة على حدة. **حدّث المصدر الواحد** الذي تقرأ منه الشاشات.
لو كانت الشاشات تستعلم كل واحدة بطريقتها، **هذا هو العطل الحقيقي** — أصلحه هنا، وإلا سيتكرر التناقض في كل تجديد.

اختبار التحقق: بعد الاعتماد، افتح الشاشات الستة وقارن التاريخ. أي اختلاف = fail.

## 4. شروط الإغلاق
> **المندوب ما يقدرش يعتبر المعاملة Completed لمجرد إنه ضغط زر «تم».**

فحص الاكتمال قبل الإغلاق — حسب ما تتطلبه الحالة:
```
[ ] Government Contract النهائي موجود
[ ] العقد النهائي مكتمل بالتوقيعات المطلوبة
[ ] Work Permit الجديد موجود (إن كان مطلوبا)
[ ] مستند الإقامة/التجديد النهائي موجود
[ ] New Expiry Date موجود ومؤكَّد
[ ] المستندات الجديدة حُفظت في Employee Documents
[ ] الـ Current Versions حُدِّثت
[ ] البيانات الأساسية الجديدة حُدِّثت
```

**عند النقص: النظام يقول للمندوب إيه الناقص بالضبط ولا يقفل.**
رسالة مثل «بيانات ناقصة» غير كافية — سمِّ الحقل أو المستند.

## 5. المراجعة النهائية
بعد اكتمال شغل المندوب، مراجعة نهائية حسب الـ workflow المعتمد.

**الهدف ليس إعادة تنفيذ شغل المندوب**، بل التأكد أن:
- المستندات النهائية موجودة
- البيانات الجديدة صحيحة
- تاريخ الانتهاء الجديد صحيح
- النسخ الجديدة أصبحت Current والقديمة History
- ملف الموظف تحدّث بالكامل

## 6. عند الاكتمال
```
Renewal Transaction        → Completed
Task المندوب               → Closed
Tasks المرتبطة بالموظف     → Closed
تنبيه انتهاء الإقامة القديم → Closed
Operations Center          → لم تعد الإقامة القديمة Critical
Renewals                   → لم تعد تُعرض كمستحقة
Expiry Engine              → يعتمد التاريخ الجديد
```

**ولا يُنشأ Alert جديد لنفس النسخة القديمة مرة أخرى.**
هذا يحتاج ربط التنبيه بـ `document_version_id` لا بـ `employee_id` فقط — وإلا سيعيد الفحص اليومي إنشاء تنبيه على المستند القديم.

**الموظف يتلقى Notification بالاكتمال — لا Task جديدة**، لأنه لم يعد مطلوبا منه إجراء.

## 7. Timeline النهائي
عند فتح معاملة مكتملة، يجب أن تُقرأ القصة كاملة من التنبيه الأول إلى المستند النهائي، وكل حدث فيه:
```
Actor · Role · Timestamp · Employee · Company · Renewal ID · المرجع المرتبط
```

## معيار النجاح النهائي
ثلاثة أسئلة، والإجابة على الثلاثة يجب أن تكون نعم:
1. أفتح المعاملة المكتملة → أعرف القصة كاملة؟
2. أفتح Employee Documents → المستندات الجديدة هي Current والقديمة في History قابلة للتنزيل؟
3. أفتح Employee Profile و Renewals و Operations Center و PRO Dashboard → كلهم متفقون على نفس التاريخ ونفس الحالة؟

## البنود المغطاة
`RNW-14` إلى `RNW-21`
