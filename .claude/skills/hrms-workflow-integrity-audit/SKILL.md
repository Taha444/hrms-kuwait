# مراجعة سلامة المسارات

## 1. آلة الحالات — الجرد أولا
استخرج من الكود لكل نوع معاملة:
```
الحالات الممكنة · الانتقالات المسموحة · من يملك كل انتقال
شروط الدخول لكل حالة · المخارج من كل حالة
```

ثم اسأل لكل حالة: **هل يوجد سيناريو تصبح فيه بلا مخرج؟**

**بلاغ موثق:** معاملة التجديد تصل `pending_hr_verify` بلا بيانات حكومة، فلا `finalize` (409) ولا HR Verify (بيانات ناقصة) — **مقفولة من الناحيتين**.
افحص هذا وابحث عن نظائره في: `GOVERNMENT_PROCESSING` · `FINAL_PACKAGE_UPLOADED` · `OCR_PROCESSED` · `DATA_CONFIRMED` · `FINAL_VERIFICATION`.

## 2. الانتقالات الممنوعة
جرّب كل انتقال غير مسموح مباشرة على الـ API:
```bash
# قفزة من draft إلى completed
curl -X PATCH "$B/api/requests/5" -d '{"status":"completed"}'
# تراجع من completed إلى pending
# انتقال بلا استيفاء الشرط
```
المتوقع: `409` أو `422` **يشرح السبب ويسمّي الناقص** — لا رفض صامت.

## 3. شروط الدخول تُفحص على الخادم
لكل انتقال له شرط، تجاوز الواجهة واضربه مباشرة:
```
Payroll Finalize بلا Attendance Closed
إغلاق التجديد بلا تاريخ انتهاء جديد
إخلاء طرف FINAL وجهة ما زالت OPEN
إصدار مستند نهائي بلا توقيع مطلوب
اعتماد بلا صلاحية الحد المالي
```

## 4. الأثر التشغيلي — الفحص الأهم
لكل مسار: **هل وقع الأثر فعلا؟**

| المسار | الأثر المطلوب |
|---|---|
| إجازة معتمدة | خصم الرصيد + تحديث الحضور |
| تصحيح حضور مكتمل | **سجل الحضور تغيّر فعلا** |
| سلفة معتمدة | جدول سداد في Payroll |
| مصروف معتمد | قيد دفع |
| تجديد مكتمل | تاريخ انتهاء جديد في **كل** الشاشات + مستندات Current + تنبيهات مغلقة |
| مستند مُصدَر | ملف حقيقي في التخزين ببصمة |

**اختبر بمقارنة قبل/بعد على قاعدة البيانات، لا بقراءة حالة الطلب.**

## 5. النمط الخطر: الحالة تتقدم والأثر لا
```
هل الانتقال والأثر في transaction واحدة؟
عند فشل الأثر، هل تتراجع الحالة؟
هل توجد حالة صريحة Failed / Not Applied؟
هل يُسجَّل Audit نجاح لعملية فشلت؟
```
**بلاغان موثقان:** تصحيح حضور وصل Completed بلا تطبيق · فشل توليد PDF لا يمنع الانتقال.

## 6. التزامن
```bash
# اعتمادان متزامنان لنفس المهمة
for i in 1 2; do curl -X POST "$B/api/tasks/5/approve" -H "..." & done; wait
# مستخدمان مختلفان يعتمدان نفس المهمة معا
# Payroll run متزامن لنفس الشركة والفترة
# Claim من عضوين في نفس مجموعة ONE_OF
```
المتوقع: واحد ينجح والباقي `409`، **وأثر واحد وسجل تدقيق واحد**.

## 7. المعيّن والتفويض
```
[ ] المعيّن يُحسب ديناميكيا من العلاقة لا من اسم ثابت
[ ] عند غياب المعيّن يوجد fallback — لا مهمة بلا مالك
[ ] التفويض المنتهي مرفوض
[ ] Claim / ONE_OF: عضو واحد يأخذها والباقون يفقدون الـ action
[ ] ALL_OF لا يُغلق قبل كل الجهات المطلوبة
[ ] تخطي الموافق المكرر يعمل
```

## 8. NEEDS_INFO والاستئناف
```
[ ] العودة على نفس request_id — لا طلب جديد
[ ] Timeline محفوظ كاملا
[ ] العودة لنفس المراجع
[ ] policy_version و workflow_version الأصليان محفوظان
```

## 9. المسارات البديلة
لكل معاملة، اختبر: الإلغاء · الرفض · انتهاء المهلة · فشل خطوة خارجية (OCR، PDF، بريد) · حذف الموظف أثناء المعاملة.

المتوقع في كلها: **حالة واضحة، لا تعليق صامت، ولا فقد بيانات.**

## التسجيل
- حالة بلا مخرج → `critical`
- انتقال ممنوع يُقبل → `critical`
- حالة تتقدم بلا أثر → `high`
- تزامن ينتج أثرين → `high`
- مهمة بلا مالك → `high`
