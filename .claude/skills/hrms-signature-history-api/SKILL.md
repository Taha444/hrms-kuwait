# سجل التوقيعات — تحقيق قبل إصلاح

## الوضع
**استبدال التوقيع شغّال بالكامل:** Pending · القديم يبقى Active · موافقة ورفض HR · التدقيق كله سليم.

**لكن** `/api/me/signature/history` يرجع **فارغا** رغم وجود `v1` و `v2` ومحاولة مرفوضة.

## القاعدة
> **لا تصلح endpoint قبل معرفة إن كان مستخدما.**

بناء ميزة لـ endpoint مهجور شغل ضائع، وحذف endpoint مستخدم كسر. **التحقيق أولا.**

## التحقيق — بهذا الترتيب

### 1. هل تستدعيه الواجهة؟
```bash
grep -rn "signature/history" --include=*.js --include=*.jsx --include=*.ts --include=*.tsx --include=*.vue .
```
وافتح شاشة التوقيع في المتصفح مع Network tab — **هل يُستدعى فعلا؟**

### 2. هل توجد شاشة «سجل التوقيعات»؟
ابحث في الواجهة عن أي عرض لتاريخ التوقيعات. موجودة؟ مخططة؟ غير موجودة؟

### 3. لماذا يرجع فارغا؟
افحص الاستعلام:
- يفلتر على `user_id` صحيح؟
- يفلتر على `status = 'active'` فيستبعد القديمة والمرفوضة؟
- يقرأ من الجدول الصحيح؟ (قد تكون النسخ في جدول إصدارات منفصل)
- مشكلة نطاق شركة؟

### 4. أين البيانات فعلا؟
```sql
SELECT * FROM signature_versions WHERE employee_id = ? ORDER BY created_at;
SELECT * FROM signatures WHERE employee_id = ?;
```
البيانات موجودة (التدقيق يثبت ذلك) — المطلوب معرفة **أين** وكيف يصل إليها الـ endpoint.

## القرار — بعد التحقيق
| النتيجة | الإجراء |
|---|---|
| مستخدم في الواجهة | **أصلح الاستعلام** — عطل حقيقي |
| غير مستخدم وشاشة السجل مطلوبة | أصلحه **وابنِ الشاشة** |
| غير مستخدم ولا شاشة مخططة | **احذفه** أو علّمه `deprecated` بتاريخ |

**لا تختر قبل التحقيق.** اعرض النتيجة على المستخدم واسأله أي الثلاثة يريد.

## لو قررتم الإصلاح
السجل يعرض لكل إصدار:
```
رقم الإصدار · الحالة (Active/Superseded/Rejected/Pending)
تاريخ الرفع · من رفعه · سبب الاستبدال
من وافق أو رفض ومتى · معاينة قابلة للعرض
```
والمحاولات المرفوضة **تظهر** — جزء من التاريخ.

قواعد إلزامية:
- **لا يُعرض Storage URL ولا مسار الملف** للمستخدم
- صلاحية عرض السجل = صلاحية عرض التوقيع
- الموظف يرى سجله · HR يرى ضمن شركته · **PRO لا يرى**
- تنزيل نسخة قديمة مسجّل في Audit
- **المستند المُصدَر سابقا يحتفظ بنسخة التوقيع وقت إصداره** — لا يتغير بتغيّر التوقيع لاحقا

## بحث أوسع
هذا يفتح سؤالا: **كم endpoint آخر مهجور أو مكسور بلا أن يلاحظه أحد؟**

جرد سريع: قارن قائمة المسارات المعرّفة بما تستدعيه الواجهة فعلا. ما لا يُستدعى إما ميت أو ميزة ناقصة — وكلاهما يستحق التسجيل. وأي endpoint حي بلا صلاحية صحيحة **ثغرة**، لا مجرد كود ميت.

## البنود
`SIG-H1` التحقيق والقرار · `SIG-H2` التنفيذ حسب القرار
