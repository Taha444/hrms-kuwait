# تقرير مراجعة الـ Backend

## الأداة
```bash
python3 .claude/hrms/scripts/findings.py --report > audit-report.md
python3 .claude/hrms/scripts/findings.py --sev critical
python3 .claude/hrms/scripts/findings.py --roots
```

## بنية التقرير

### 1. الرأس
```
التاريخ · الرابط · البيئة · Build · Commit · Migration Version
الحسابات المستخدمة (الأدوار لا كلمات السر)
ما فُحص · ما لم يُفحص ولماذا
```

### 2. الملخص التنفيذي — نصف صفحة
```
عدد النتائج بالخطورة: critical / high / medium / low
أخطر ثلاث نتائج بجملة واحدة لكل منها
الحكم: هل النظام صالح للتسليم الآن؟ ولماذا
```
اكتبه **بلغة يفهمها غير التقني** — هذا ما يُقرأ فعلا.

### 3. النتائج بالتفصيل
لكل نتيجة:
```
المعرّف · العنوان · الخطورة · المنطقة
الـ endpoint والدور والشركة
ما توقعته · ما حدث
خطوات التكرار (أمر كامل قابل للصق)
الدليل (مسار الملف في evidence/)
الأثر على العميل — بلغة العمل لا التقنية
الإصلاح المقترح
```

**بلا خطوات تكرار، النتيجة ليست نتيجة.**

### 4. الجذور المشتركة — أهم قسم
```bash
python3 .claude/hrms/scripts/findings.py --roots
```
عشرون نتيجة قد تكون خمسة جذور. اعرض:
```
الجذر · النتائج التابعة · إصلاح واحد يغلق كم بندا
```
الجذور المتكررة في هذا النظام تحديدا:
```
مصدر صلاحيات غير موحّد بين Menu/Route/API/Button
كل شاشة تحسب بنفسها بدل مصدر بيانات واحد
لا تعريف واضح لما هو «مهمة»
قيود في الكود بلا مقابل في القاعدة
الحالة تتقدم والأثر لا يقع
انتقالات بلا شروط دخول مفحوصة على الخادم
```

### 5. ترتيب الإصلاح
لا ترتّب بالخطورة وحدها بل بالاعتماد التقني:
```
1. ما يمنع الاختبار (endpoint يرجع 500 · صلاحيات مكسورة)
2. critical أمني (تسريب · تجاوز صلاحيات · IDOR)
3. فساد بيانات (قيود ناقصة · معاملات ناقصة · حالة بلا أثر)
4. جذور تغلق عدة بنود
5. الباقي بالخطورة
```

### 6. ما لم يُفحص — لا تحذفه
```
اختبارات لم تُنفَّذ لعدم توفر حساب أو بيانات
مسارات تحتاج بيئة خاصة
اختبار حمل وأداء
اختبار اختراق بأدوات متخصصة
فحص المكتبات والاعتماديات
سباقات تزامن نادرة
أخطاء منطق عمل تحتاج معرفة السياسة
```

### 7. حدود المراجعة — بصراحة
> هذه مراجعة منهجية تكشف **فئات** من الأخطاء، وليست ضمانا بخلو النظام منها.
> نظام يحمل بيانات موظفين حقيقية لشركة يستحق **فحصا أمنيا مستقلا من طرف ثالث** قبل التسليم.

**اكتب هذا في التقرير.** العميل يستحق أن يعرف حدود ما اشتراه.

## قواعد الكتابة
- **لا تبالغ ولا تهوّن.** `critical` تعني critical.
- **لا تدّعِ الشمول.**
- **لا تكتب "آمن"** لبند لم تجربه — اكتب «لم يُختبر» والسبب.
- **لا كلمات سر ولا توكنات** في التقرير أو الأدلة.
- الأدلة تُنقّى من البيانات الشخصية قبل الإرفاق.
- افصل **الحقيقة** (ما رأيته) عن **التفسير** (ما تظنه سببا).

## المتابعة
كل نتيجة تتحول إلى بند في سجل العيوب، وكل بند إلى اختبار آلي يمنع عودته.
مراجعة لا تنتهي باختبارات تمنع التكرار ستُعاد كاملة بعد ثلاثة أشهر.
