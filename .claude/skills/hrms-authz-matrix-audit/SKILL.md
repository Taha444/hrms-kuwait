# مراجعة الصلاحيات والعزل

## لماذا هذه المرحلة مبكرة
لو الحارس معطّل، **كل نتيجة بعدها مشكوك فيها** — لن تعرف هل الشاشة عملت لأنها مسموحة أم لأن الفحص غائب.

## 1. المصفوفة الآلية
```bash
source .claude/hrms/scripts/env.sh
python3 .claude/hrms/scripts/probe_matrix.py --read-only
```
يسجّل دخول بكل دور، ويضرب كل endpoint من الجرد، ويبني مصفوفة `دور × مسار × كود الحالة`.

اقرأ النتيجة بحثا عن:
- **`200` لدور يُتوقع منعه** → ثغرة محتملة، **افحص الجسم** — قد يكون 200 بقائمة فارغة (سلوك مقبول) أو ببيانات فعلية (ثغرة)
- **`500`** → عطل مستقل يُسجَّل
- **`403` لدور يُفترض السماح له** → عطل صلاحيات معاكس (مثل بلاغ HR الممنوع من مراجعة الحضور)

## 2. IDOR — الأهم ولا تكشفه المصفوفة
المصفوفة تفحص «هل يصل للمسار». **IDOR يفحص «هل يصل لسجل غيره».**

لكل مسار يقبل معرّفا:
```bash
# سجل يخصني
curl -H "Authorization: Bearer $EMPLOYEE_TOKEN" "$B/api/employees/10"   # المتوقع 200
# سجل زميل في نفس الشركة
curl -H "Authorization: Bearer $EMPLOYEE_TOKEN" "$B/api/employees/11"   # المتوقع 403
# سجل من الشركة الأخرى
curl -H "Authorization: Bearer $GUF_HR_TOKEN"   "$B/api/employees/99"   # المتوقع 403/404
# معرّف غير موجود
curl -H "Authorization: Bearer $HR_TOKEN"       "$B/api/employees/999999"
```

```bash
python3 .claude/hrms/scripts/probe_matrix.py --idor
```

**في نظام متعدد الشركات، IDOR أخطر ثغرة وأكثرها شيوعا.** غياب فحص النطاق لا يظهر إلا بتجربة معرّف غير مملوك.

المتوقع: `403` أو `404` **بلا تسريب في جسم الرد**. رسالة مثل «الموظف أحمد غير مصرح» تسرّب الاسم.

## 3. العزل بين الشركات
- مستخدم GUF لا يصل لأي سجل في MUF — بالمسار وبالفلتر وبالتصدير
- تبديل `company_id` في جسم الطلب أو الترويسة **لا يغيّر النطاق**
- القوائم مفلترة بالنطاق **في الاستعلام** لا بعده في التطبيق
- المندوب يرى الشركات المسندة له فقط

**فحص خبيث مطلوب:** أرسل `company_id` مخالفا في جسم POST — هل يُحترم أم يُتجاهل لصالح نطاق التوكن؟ الصحيح: يُتجاهل.

## 4. صلاحيات الحقول
الوصول للسجل لا يعني الوصول لكل حقوله.

| الدور | ممنوع من |
|---|---|
| Accountant | Passport · Civil ID · Contract · Documents · Leave · Warnings · EOS |
| PRO | Basic Salary · Hire Date · Contract fields · إنشاء موظف |
| Manager | مرفقات التظلم السرية |
| Employee | تواريخ إجازته (قرار خصوصية) · بيانات غيره |

**افحص جسم الرد حقلا حقلا**، لا كود الحالة فقط. `200` بحقل ممنوع = تسريب.

```bash
python3 .claude/hrms/scripts/probe_matrix.py --fields
```

## 5. المنع في ثلاث طبقات
```
UI  →  API  →  Storage endpoint
```
البلاغ الموثق ينص على الثلاثة. **إخفاء الزر ليس منعا.** جرّب رابط التخزين المباشر بحساب ممنوع.

## 6. تجاوز المراحل والاعتماد الذاتي
```
[ ] غير المعيّن الحالي لا ينفّذ action ولو فتح الرابط مباشرة  → 403
[ ] المهمة المنتهية (stale) مرفوضة
[ ] لا اعتماد ذاتي — مقدّم الطلب لا يعتمده
[ ] لا اعتماد لمرحلتين متتاليتين لنفس الشخص
[ ] الانتحال لا يمنح اعتمادا ذاتيا
[ ] الضغط المكرر ينتج أثرا واحدا
```
**بلاغ موثق:** مدير الشركة اعتمد مرحلة مسؤول الفرع ثم مرحلته ثم مرحلة HR بنفس الحساب. اختبر هذا تحديدا.

## 7. مصدر الصلاحية
- هل `Menu` و `Route` و `Button` و `API` يقرأون من **نفس المصدر**؟
- هل توجد صلاحية في الـ API بلا مسار ظاهر؟ (تسريب)
- هل يوجد رابط ظاهر بلا صلاحية؟ (خطأ عرض)
- هل بقيت صلاحية عامة مثل `approve_request` لكل الأنواع؟

## 8. المصادقة نفسها
```
[ ] كل بيانات الدخول التجريبية معطّلة
[ ] Rate limit و Lockout يعملان — جرّب 10 محاولات
[ ] المستخدم المعطّل لا يدخل
[ ] الجلسات تنتهي بعد تغيير كلمة السر أو التعطيل
[ ] 2FA مطبّق فعليا في مسار الدخول (افحص NTP أولا)
[ ] التوكن: مدة معقولة · لا يُقبل بعد انتهائه · لا يُقبل توكن دور آخر
```

## التسجيل
كل `200` غير متوقع = نتيجة بخطورة `critical` مع الأمر الكامل وجسم الرد كدليل.
