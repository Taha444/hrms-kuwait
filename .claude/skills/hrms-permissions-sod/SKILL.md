# HRMS Permissions & Segregation of Duties (V2.2 §4.5، §11، §29)

## القاعدة الأولى
**لا تكفي صلاحية واحدة باسم `approve_request` لكل الأنواع.** يجب فصل الصلاحيات التالية:
```
request.create        request.view          task.claim
decision.approve      decision.reject
validation.complete   execution.complete
document.generate     document.file
workflow.configure
```
كل صلاحية تُمنح بنطاق: `company / branch / team / self`. لا صلاحية بلا نطاق.

## 2. الفصل بين الواجبات — قواعد صلبة
- **لا يعتمد المستخدم طلبه**، ولا يستلم مهمة نتيجة انتحال أو تفويض يؤدي إلى self-approval.
- **منشئ تعديل الحساب البنكي لا يفعّله منفردا** — التفعيل يحتاج مراجعة مستقلة (dual control).
- **صاحب قرار الخصم لا يكون المراجع النهائي لاعتراض الخصم.**
- في التظلم: يُستبعد المشكو في حقه **وسلسلته الإدارية المتعارضة** من الـ resolver ومن الاطلاع.
- في EOS: الحساب (Payroll) والمراجعة (Finance مستقل) والتوقيع (Signatory) **ثلاثة أشخاص لا شخص واحد**.

## 3. الخصوصية وحجب الحقول
- Finance يرى البيانات المالية اللازمة فقط.
- Manager **لا يرى** مرفقات تظلم سرية.
- PRO **لا يرى** تفاصيل الراتب.
- السجلات تعرض `current assignee` و `SLA` **دون كشف البيانات الحساسة** لمن لا يملك Field Permission.
- **الحقول الحساسة محجوبة حسب الدور حتى عندما يملك المستخدم صلاحية مشاهدة حالة الطلب.**
- IBAN: مقنّع في الإيصال العام، كامل فقط لصلاحية محددة.
- الرقم المدني: لا يُعرض كاملا في مستند عام إلا عند الحاجة والغرض المصرّح.

## 4. Super Admin
يستطيع تهيئة المسار ومراجعة السجل — لكن **تجاوزه التجاري يحتاج Break-glass مسجلا ومسببا**، ولا يصبح موافقا افتراضيا عند غياب الدور.

## 5. التنفيذ التقني الإلزامي
- الفحص في الـ API أولا، والـ UI طبقة عرض فقط. اختبر دائما بفتح الرابط المباشر.
- `direct URL action` من غير المعيّن → **403**، وبلا كشف أي بيانات حساسة في جسم الرد.
- `stale task` (المهمة انتقلت أو claimed من غيره) → **رفض**، لا تنفيذ متأخر.
- `impersonation` يُسجَّل بحقلين منفصلين: `actor` و `original_actor` في `decision_log`.
- كل `Generate/Preview/Sign/Issue/Download/Print/File/Revoke` يسجل Audit event.

## 6. سجل التدقيق — الحد الأدنى لكل قرار أو تحقق أو تنفيذ
```
actor · original_actor · outcome · reason · before/after · timestamp · IP
```
كل رفض أو إعادة معلومات **يحتاج سببا**، وبعض الأنواع تحتاج `reason_code` ومرفقا.

## 7. صلاحية المستند مستقلة عن صلاحية الطلب
القدرة على رؤية `request_instance` **لا تمنح** تلقائيا القدرة على تنزيل `document_artifact`، والعكس صحيح. عرّفهما كحارسين منفصلين.
