# اختبار مسار التجديد

## قاعدة أولى
**الاختبار على Staging أو بيانات Demo فقط.** رفع مستندات ومعاملات حكومية على بيانات عميل حقيقية ممنوع.

## تجهيز حالة الاختبار
```sql
-- موظف باقامة تنتهي خلال 6 أيام (مطابقة للحالة الحالية)
-- تأكد أن له: حساب مستخدم مربوط · فرع · مندوب مسند · بيانات كاملة للعقد
```
تحتاج ثلاثة حسابات جاهزة: **PRO** و **الموظف صاحب الإقامة** و **HR**.
وتحتاج ملف PDF أو صورة يمثّل النسخة الموقّعة، وملفات تمثّل الحزمة النهائية.

## الاختبار الكامل — 20 خطوة

### المرحلة أ: من التنبيه إلى المعاملة
1. **[PRO]** افتح معاملات تجديد الإقامة → التنبيه ظاهر باسم الموظف والفرع والتاريخ والأيام المتبقية
2. **[PRO]** اضغط البطاقة → تفتح لوحة تفصيل وفيها زر «بدء معاملة التجديد» — *لا تجاهل صامت*
3. **[PRO]** اضغط بدء → تُنشأ معاملة بـ `case_no` وتنتقل من «لم يُفتح لها ملف» إلى «معاملات تجديد»
4. **[PRO]** اضغط بدء مرة ثانية على نفس المستند → **معاملة واحدة فقط** (idempotency)
5. **افحص التطابق**: Renewals و Operations Center و PRO Dashboard — نفس البيانات

### المرحلة ب: العقد
6. **[PRO]** توليد العقد الحكومي → Preview يفتح والحقول مملوءة من النظام
7. **تحقق**: لم يُنشأ Company Employment Contract جديد
8. **جرّب حقلا ناقصا**: أفرغ حقلا إلزاميا في بيانات الموظف وحاول التوليد → يوقف ويسمّي الحقل
9. **[PRO]** راجع وأرسل للموظف

### المرحلة ج: الموظف
10. **[الموظف]** سجّل دخول → **Task حقيقية** ظاهرة + Notification
11. **[الموظف]** افتح العقد · عاينه · نزّله → الحدث مسجّل في Timeline
12. **[الموظف]** ارفع نسخة موقّعة → المهمة تكتمل وتُغلق
13. **تحقق في قاعدة البيانات**: الملف مرتبط بـ `renewal_case_id` و `employee_id` و `source_contract_artifact_id`
14. **تحقق**: النسخة المولّدة الأصلية ما زالت موجودة ولم تُستبدل

### المرحلة د: عودة للمندوب والحكومة
15. **[PRO]** Action ظهر → اعرض ونزّل نسخة الموظف
16. **[PRO]** انتقل لـ «جاري التجديد» → سجّل مرجعا حكوميا ورسوما
17. **[PRO]** ارفع الحزمة النهائية: العقد النهائي + إذن العمل + الإقامة الجديدة

### المرحلة هـ: OCR والإغلاق
18. **تحقق**: OCR عرض القيم **للمراجعة** ولم يطبّقها · ضعيف الثقة مميّز · الناقص يطلب إدخالا
19. **[PRO]** أكّد البيانات → جرّب الإغلاق **مع نقص متعمد** → يرفض ويسمّي الناقص
20. **[HR]** مراجعة نهائية → إغلاق

## التحقق بعد الإغلاق — الأهم
```
[ ] Employee Documents: الجديدة Current · القديمة History قابلة للتنزيل
[ ] Employee Profile: تاريخ الانتهاء الجديد
[ ] Renewals: لم تعد تعرضها مستحقة
[ ] Operations Center: لم تعد Critical
[ ] PRO Dashboard: محدّث
[ ] الشاشات الستة متفقة على نفس التاريخ
[ ] مهام المندوب والموظف مغلقة
[ ] التنبيه القديم مغلق
[ ] الموظف تلقى Notification لا Task
[ ] Timeline يحكي القصة كاملة بـ Actor و Role و Timestamp لكل حدث
[ ] النسخ الثلاث للعقد موجودة ومتمايزة
```

## اختبار الفحص اليومي
```
شغّل Daily Scan مرتين متتاليتين → لا تكرار في المهام أو التنبيهات
شغّله بعد الإغلاق → لا Alert جديد لنفس النسخة القديمة
```

## فحوص قاعدة البيانات
```sql
-- معاملات مكررة لنفس المستند
SELECT current_document_id, COUNT(*) FROM renewal_cases
WHERE status NOT IN ('COMPLETED','CANCELLED') GROUP BY 1 HAVING COUNT(*) > 1;

-- مستندات موقّعة غير مرتبطة بمعاملة
SELECT id, type FROM document_artifacts
WHERE type LIKE 'GOV_CONTRACT%' AND renewal_case_id IS NULL;

-- معاملات مكتملة بلا تاريخ انتهاء جديد
SELECT id, case_no FROM renewal_cases
WHERE status='COMPLETED' AND new_expiry_date IS NULL;

-- مستندات نسختها الجديدة Current والقديمة مفقودة
SELECT employee_id, doc_type, COUNT(*) FROM employee_documents
WHERE doc_type='residency' GROUP BY 1,2 HAVING COUNT(*) < 2;

-- تنبيهات مفتوحة على مستند نسخته القديمة
SELECT a.id FROM expiry_alerts a JOIN employee_documents d ON d.id=a.document_id
WHERE a.status='open' AND d.version_status='history';

-- مهام مفتوحة لمعاملات مغلقة
SELECT t.id FROM tasks t JOIN renewal_cases r ON r.id=t.renewal_case_id
WHERE t.status='open' AND r.status IN ('COMPLETED','CANCELLED');
```

## المسارات البديلة — اختبرها أيضا
| السيناريو | المتوقع |
|---|---|
| الموظف لا يرفع والإقامة تنتهي | تصعيد ظاهر · المعاملة قابلة للاستكمال · لا إخفاء |
| رفض من الجهة الحكومية | سبب مسجّل · إعادة المحاولة بنفس المعاملة |
| إلغاء المعاملة | سبب إلزامي · المهام تُغلق · التنبيه يعود إن كانت مستحقة |
| تجديد مبكر (31-90 يوما) | يمر بـ Manager و HR قبل المندوب |
| موظف بلا حساب مستخدم | يُكتشف قبل الإرسال ولا يعلق المسار صامتا |
| مندوب من شركة أخرى | لا يرى المعاملة إطلاقا |
