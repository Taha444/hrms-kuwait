# HRMS Request Catalog & Route Matrix (V2.2 §5، §6، §12)

## الهدف الرقمي
- من **53 نوعا** ظاهرة للأدوار → **29 نوعا Canonical**.
- كتالوج الموظف: **15-18 خدمة ذاتية مجمّعة بلا تكرار** (كان 26).
- كل دور يرى `allowlist` صحيحا مرتبطا بعمله، لا القائمة الكاملة.

## 1. كتالوج الموظف الواقعي (§5)
| المجموعة | الخدمات الظاهرة |
|---|---|
| الوقت والحضور | إجازة، استئذان، تصحيح حضور |
| الشهادات والخطابات | شهادة/خطاب مع Subtype: راتب، خبرة، لمن يهمه الأمر، NOC |
| البيانات | تعديل بيانات شخصية، حساب بنكي، وثيقة هوية/جواز/مدني |
| المالية | سلفة/قرض، مصروفات، اعتراض راتب/خصم |
| علاقات العمل | تظلم سري، استقالة، طلب معلومات عام |
| الإقامة | طلب تجديد مبكر أو تحديث مستند مؤثر |
| التطوير الوظيفي | تدريب، طلب مراجعة ترقية/راتب |

**ليست طلبات — لا تظهر في الكتالوج:**
- قسيمة الراتب → داخل `My Documents`
- متابعة الإقامة → شاشة حالة، وليست طلبا جديدا
- الرد على إنذار / الإقرار / استكمال المعلومات → **إجراءات سياقية `contextual_only` داخل المعاملة الأصلية**، لا خدمة مستقلة عامة

## 2. قواعد العرض لكل دور (§4)
| الدور | الكتالوج | صندوق المهام | ما لا يفعله افتراضيا |
|---|---|---|---|
| Employee | 15-18 خدمة ذاتية | استكمال معلومات أو إقرار يخصه | لا يرى الطلبات الداخلية ولا يعتمد طلبه |
| Manager | تكليف إضافي، ترشيح تدريب/ترقية، بلاغ واقعة | قرارات موظفي نطاقه فقط | لا يرى كل طلبات الشركة ولا حقول Finance السرية |
| HR | حالات HR والإجراءات الداخلية المخوّلة | تحقق وسياسة وتنفيذ | لا يعتمد الأثر المالي منفردا |
| Payroll/Finance | عمليات مالية محددة | تحقق مالي، اعتماد ضمن الحد، دفع/Payroll | لا يقرر صحة الواقعة التأديبية أو سياسة HR |
| PRO/Delegate | معاملات حكومية وملفات تنفيذ | مهام تنفيذ حكومي وحالات متابعة | لا يملك Approve/Reject عام |
| Super Admin | إعداد النظام فقط | لا مهام أعمال إلا بدور تجاري منفصل | لا يتجاوز الفصل بين الواجبات |
| Auditor | لا يبدأ طلبات | قراءة السجل والتقارير حسب النطاق | لا يعدّل ولا يعتمد |

## 3. المصفوفة الواقعية للمسارات
**اقرأ `references/wf-matrix.md`** — فيها المسار المقترح والشروط والاستثناءات لكل كود من `WF-001` إلى `WF-029`، ومخرَج كل مسار (`OD-xxx` + نوع النتيجة).
اقرأها كاملة قبل تعريف أو تعديل أي مسار، ولا تعتمد على الذاكرة.

## 4. القواعد العامة المستخلصة من المصفوفة
- **Manager ليس خطوة افتراضية** في: شهادة الراتب، تحديث الجواز/المدني، تجديد الإقامة، التظلم.
- **Finance يدخل فقط عند وجود أثر مالي فعلي** أو تجاوز حد مسجل في `policy_rule`.
- **HR يدخل كـ VALIDATION لا كـ DECISION** إلا في الأنواع المخوّل بها صراحة (الخصم، التظلم، الإجراء التأديبي).
- **PRO ينفّذ ولا يعتمد** — لا يقرر إجازة ولا أثرا ماليا.
- الاستقالة **ليست "طلب إذن"** — المدير يُقر ولا يرفض الإشعار.
- الإقامة والتجديد تُدار كـ **Case بمراحل**، لا كسلسلة موافقات متكررة.
- الطلب العام `WF-029` **لا يحمل Approve/Reject ولا ينتج PDF رسميا** قبل التحويل لنوع Canonical.

## 5. تنظيف الكتالوج — الترتيب الإلزامي
1. اجرد الأنواع الحالية واربطها بالـ 29 Canonical.
2. علّم الأنواع الداخلية بـ `contextual_only = true` (الرد على إنذار، الإقرار، استكمال معلومات).
3. علّم النسخ القديمة كـ Legacy Alias — **لا تحذفها** قبل استيفاء شروط سكيل `hrms-legacy-migration`.
4. اضبط `requester_roles` و `visibility_policy` لكل نوع.
5. أثبت بالاختبار أن Employee يرى 15-18 خدمة بلا تكرار وبلا أكواد داخلية.
