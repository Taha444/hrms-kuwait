# HRMS Legacy Migration (V2.2 §24.5، §12 المرحلة 6)

## الحقيقة الأساسية
**الرقم 54 في V1.4 كان عدد أكواد تاريخية، لا عدد تصميمات تُبنى يدويا.**
الصواب: `9 Layouts` + `25 OD` + `6 RPT` + `2 SYS`، والباقي **Aliases** لا نسخا.
كذلك: 53 نوع طلب → **29 Canonical**، والباقي إما مدموج أو `contextual_only` أو محذوف بعد الترحيل.

## 1. بنية التعريف
كل تعريف مستند يخزّن:
```
canonical_code   → OD-002
profile_code     → BANK
layout_code      → LAY-01
legacy_aliases[] → ["PRN-004"]
```
أي استدعاء قديم لكود PRN **يحله Alias Resolver إلى نفس التعريف Canonical** — **ولا ينسخ قالبا جديدا أبدا**.

## 2. الأرشيف
- المستندات المُصدَرة قديما تُحفظ **كأرشيف غير قابل للتعديل** مع `legacy_template_code`.
- الإصدارات الجديدة تحمل `document_definition_version` و `layout_version`.
- **ممنوع إعادة توليد مستند قديم بقالب جديد.** الطلب القديم يحتفظ بنسخته (DOC-20).

## 3. شروط حذف أي Alias — كلها معا
- [ ] نجاح ترحيل البيانات فعليا (لا صفوف تشير للكود القديم)
- [ ] تحديث كل API و Job و Permission يستدعي الكود القديم
- [ ] مرور اختبارات Regression كاملة
- [ ] انتهاء **مدة توافق معلنة** للمستهلكين الخارجيين

قبل استيفائها كلها: **لا `DROP`، لا `DELETE`، لا إعادة تسمية.**

## 4. فصل مسؤوليات التعديل
- **إدارة المحتوى** تعدّل النصوص والحقول داخل تعريف المستند أو Profile.
- **إدارة الهوية** تعدّل `Layout` واحدا فتنعكس الهوية على كل المستندات التابعة **عند نشر نسخة جديدة** — لا فورا على المُصدَر.

## 5. ترحيل الطلبات المفتوحة (المرحلة 6)
| الخطوة | القاعدة |
|---|---|
| جرد | كل طلب مفتوح يُصنَّف: يُرحَّل / يُغلَق بقرار / يُترك على المسار القديم حتى انتهائه |
| المسار | الطلب المرحَّل يحتفظ بـ `workflow_version` و `policy_version` الأصليين (RW-18) |
| المهام | كل مهمة مفتوحة تحصل على `assignee` صالح في النموذج الجديد — **لا مهمة بلا مالك** |
| التحقق | **لا طلبات يتيمة ولا مزدوجة** بعد الترحيل — استعلام إلزامي |
| rollback | مجرَّب فعليا على نسخة، لا مكتوب نظريا |

## 6. تعطيل المسارات القديمة
- لا تُعطَّل قبل: مراقبة SLA فعّالة + تدريب المستخدمين + ترحيل المفتوح.
- التعطيل **تدريجي بالدور والشركة**، لا دفعة واحدة.
- بعد التعطيل تبقى القراءة والأرشيف متاحين للتدقيق.

## 7. ملاحظة مصدر مهمة (§24)
الملف `Kuwait_HRMS_Print_Templates_Master_AR_EN_45-2.pdf` محتواه الفعلي **تقرير UAT/QA من 19 صفحة، وليس كتاب قوالب طباعة**.
الأساس التاريخي لأكواد PRN هو **صفحات 26-39 من V1.4**.
**إذا وُجد Master آخر، تجب مقارنته بندا بندا قبل التفعيل** — لا تفترض صحته.

## معيار القبول
`STR-03` و `STR-07` في سجل الامتثال:
> يثبت المهندس أن النظام يحوي **9 ملفات Layout فقط**، وأن كل PRN تاريخي يُحل إلى OD أو RPT أو SYS معروف **دون 404 ودون اختلاف غير مقصود**.
