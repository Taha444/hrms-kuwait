# بوابة صلاحيات الاعتماد في الواجهة

## التشخيص المؤكَّد
> الـ Backend شغّال. المشكلة **Frontend permission gate**.

المعتمد الحالي لا يرى **اعتماد / رفض / إرجاع** رغم أن الخادم يقبل الإجراء منه. أي أن الواجهة تحسب الصلاحية بمنطق خاص بها يخالف حكم الخادم.

## القاعدة
```
شريط الإجراءات يُبنى من استجابة الخادم — لا من منطق في الواجهة.
```

الخادم يرجع مع كل مهمة `allowed_actions` للمستخدم الحالي، والواجهة **تعرض ما جاء فيها ولا تحسب شيئا**.

هذا ليس تفضيلا معماريا: أي منطق صلاحيات مكرر في مكانين سينحرف أحدهما عن الآخر — وهذا بالضبط ما حدث.

## خطوات الإصلاح

### 1. حدد أين تُحسب الصلاحية في الواجهة
ابحث عن الشرط الذي يخفي الأزرار: مقارنة دور؟ مقارنة `user.id` بـ `assignee_id`؟ فحص قائمة صلاحيات محلية؟
اعرض الملف والسطر.

### 2. قارن بحكم الخادم
لنفس المستخدم ونفس الطلب:
```bash
curl -H "Authorization: Bearer $T" "$BASE/api/requests/<id>"      # ماذا يرجع؟
curl -X POST -H "Authorization: Bearer $T" "$BASE/api/requests/<id>/approve"  # هل يقبل؟
```
لو الخادم يقبل والواجهة تخفي → تأكد التشخيص.

### 3. أضف `allowed_actions` إن لم تكن موجودة
لكل مهمة في الاستجابة:
```json
{ "task_id": "...", "step_type": "DECISION",
  "allowed_actions": ["approve", "reject", "needs_info"] }
```
الأفعال تُشتق من `step_type` لا من اسم موحّد:
```
DECISION        → Approve · Reject · Needs Info
VALIDATION      → Valid · Invalid · Return for Correction
EXECUTION       → Start · Complete · Cannot Complete
ACKNOWLEDGEMENT → Acknowledge · Dispute
```

### 4. احذف منطق الصلاحية من الواجهة
الواجهة تعرض ما في `allowed_actions` فقط. لا شروط دور ولا مقارنات محلية.

### 5. لا تفتح ثغرة أثناء الإصلاح
هذا الإصلاح **يُظهر أزرارا كانت مخفية**. تأكد أنك تُظهرها **للمعيّن الحالي فقط**:
- [ ] المعيّن الحالي يرى أزراره
- [ ] غير المعيّن لا يراها **ولا ينفّذها بالرابط المباشر** (403 من الخادم)
- [ ] المعتمد لا يعتمد طلبه بنفسه
- [ ] الأزرار تختفي بعد انتقال المرحلة
- [ ] المهمة المنتهية مرفوضة (stale)
- [ ] الضغط المكرر ينتج أثرا واحدا

**بلاغ سابق موثق:** مدير الشركة استطاع اعتماد مرحلة مسؤول الفرع ثم مرحلته ثم مرحلة HR بنفس الحساب. لا تعالج «الأزرار مخفية» بإظهارها للجميع.

### 6. اختبر
على **GUF و MUF**، وبكل دور معتمد: Branch Supervisor · Manager · HR · Finance · PRO.
لكل واحد: هل يرى أزراره في مرحلته؟ وهل لا يراها في مراحل غيره؟

## البند
`APP-01` — المعتمد الحالي يرى اعتماد/رفض/إرجاع، وغير المعيّن لا يراها ولا ينفّذها بالرابط المباشر.
