# OCR والتحقق من البيانات المستخرجة

## القاعدة المركزية
> **الـ OCR لا يعمل Silent Update.**

النظام لا يكتفي بتخزين الملفات، لكنه أيضا **لا يطبّق ما استخرجه مباشرة على ملف الموظف**. القيم تُعرض للمراجعة والتأكيد أولا — خصوصا التواريخ والأرقام.

السبب عملي: تاريخ انتهاء خاطئ يعني تنبيه تجديد خاطئ، ويعني موظفا تنتهي إقامته والنظام يظن أنها سارية.

## ما يُستخرج حسب نوع المستند
| المستند | الحقول |
|---|---|
| الإقامة الجديدة | تاريخ الانتهاء الجديد · رقم الإقامة · تاريخ الإصدار |
| إذن العمل | رقم إذن العمل · تاريخ الانتهاء · الجهة المصدرة |
| البطاقة المدنية | رقم البطاقة · تاريخ الانتهاء |
| العقد النهائي | تاريخ العقد · المرجع |
| الإيصال | رقم الإيصال · المبلغ · التاريخ |

## المسار الإلزامي
```
رفع الحزمة النهائية
  → OCR/Document Processing على كل مستند
  → عرض القيم المستخرجة للمراجعة  ← لا تطبيق هنا
  → المندوب يؤكد أو يصحح
  → القيم المعتمدة تُطبَّق
```

## شاشة المراجعة
لكل حقل مستخرج، اعرض:
```
اسم الحقل · القيمة المستخرجة · درجة الثقة · المستند المصدر
[تأكيد]  [تصحيح]
```
- الحقول ضعيفة الثقة **مميّزة بصريا**
- الحقول التي فشل استخراجها **تظهر فارغة مع طلب إدخال** — لا تُخفى
- المستخدم يقدر يفتح المستند بجانب الشاشة للمقارنة

## قواعد الثقة
```
ثقة عالية    → معروضة مؤكَّدة مسبقا، والمستخدم يقدر يعدّل
ثقة منخفضة   → معروضة مميّزة، تحتاج تأكيدا صريحا
فشل الاستخراج → حقل فارغ مع طلب إدخال يدوي
```
**حقل أساسي ناقص أو غير مؤكد يمنع إغلاق المعاملة** — لا إغلاق ببيانات ناقصة أو خاطئة.

الحقول الأساسية التي لا يُغلق بدونها: **تاريخ الانتهاء الجديد** · رقم الإقامة الجديد · رقم إذن العمل (إن كان جزءا من المعاملة).

## تسجيل المصدر
لكل قيمة معتمدة، احفظ:
```
value · source (ocr | manual | corrected) · confidence · document_artifact_id
confirmed_by · confirmed_at
```
هذا يسمح لاحقا بمعرفة: هل هذا التاريخ قرأه النظام أم أدخله إنسان؟ ومن؟

## عطل موثق سابقا — لا تكرره
بلاغ سابق: رُفع مستند إقامة واضح فيه تاريخ انتهاء، فرجع `confidence = 0.0` و `MRZ incomplete` **وبلا Expiry Date**، والفشل كان **صامتا**.

الخطأ لم يكن في عدم القراءة فقط، بل في أن النظام مضى كأن شيئا لم يحدث. المطلوب:
- فشل الاستخراج **يظهر للمستخدم** ويطلب إدخالا
- لا يمرّ المستند كأنه معالَج
- لوج تشخيصي يحفظ سبب الفشل لتحسين النموذج لاحقا

## إن لم يكن OCR جاهزا
لو التكامل غير جاهز أو ثقته منخفضة عموما، **المسار البديل المقبول**: إدخال يدوي إلزامي مع عرض المستند بجانب الحقول.

هذا **ليس فشلا** — المعاملة تكتمل ببيانات صحيحة مدخلة يدويا. الفشل هو أن تُغلق ببيانات ناقصة أو مخمَّنة.

اطرح هذا الخيار صراحة على العميل إن تبيّن أن OCR يحتاج وقتا أطول من المتاح قبل التسليم.

## قائمة التحقق
- [ ] OCR يعمل على كل مستند في الحزمة النهائية
- [ ] القيم تُعرض للمراجعة قبل التطبيق
- [ ] لا تحديث صامت لأي حقل
- [ ] الثقة المنخفضة مميّزة وتحتاج تأكيدا
- [ ] فشل الاستخراج يظهر ويطلب إدخالا
- [ ] الحقول الأساسية الناقصة تمنع الإغلاق
- [ ] مصدر كل قيمة محفوظ (ocr/manual/corrected)
- [ ] المستخدم يقدر يفتح المستند للمقارنة

## البنود المغطاة
`RNW-12` و `RNW-13`
