**Duration**: ~15 minutes · **Audience**: Arabic managers / IT / HR

## قبل البدء — Pre-flight Checklist

- [ ] افتح **حالة النظام** `/system-health` — تأكد كل الفحوصات خضراء (DB, Tesseract, Data)
- [ ] لو البيانات مبعثرة من عرض سابق: اضغط **"إعادة تعيين بيانات الديمو"** (في نفس الصفحة) وانتظر 10 ثواني
- [ ] افتح تبويبين: `admin` و `hr` — سهّل التبديل بينهم
- [ ] جهّز صورة بطاقة مدنية كويتية (زياد) للاختبار
- [ ] اللغة العربية مُفعّلة (زر 🌐 في الأعلى)

**بيانات الدخول للديمو:**
> ⚠️ **لأمان العميل:** لا تشارك هذا الملف حرفيًا مع بيانات دخول جاهزة.
> بدلاً من ذلك، شغّل **إعادة تعيين بيانات الديمو** من صفحة /system-health، والبيانات
> الأولية تُطبع في **console الـbackend** أثناء الـseed. سلّمها للعميل عبر قناة آمنة.
>
> على production حقيقي: `python -m app.bootstrap` يولّد `super_admin` + `owner`
> بكلمات سر عشوائية تُطبع مرة واحدة في السجل (أو تُقرأ من env vars
> `BOOTSTRAP_ADMIN_PASSWORD` / `BOOTSTRAP_OWNER_PASSWORD`).

## السيناريو 1 — الترحيب والتعريف (2 دقيقة)

**بالعربي:** "أهلاً بيكم في نظام إدارة الموارد البشرية المصمّم خصيصًا لبيئة العمل الكويتية. النظام بيدعم كل الأدوار من الموظف لغاية صاحب الشركة، ومتوافق مع قانون العمل ونظام الإقامة الكويتي."

**Actions:**
1. سجّل دخول كـ`super_admin` → **Welcome Tour** تظهر تلقائيًا
2. اشرح البطاقات: 3 إجراءات سريعة حسب الدور
3. اضغط "فهمت، هيا نبدأ!" ثم انتقل لـ `/system-health`

**نقطة القوة:** *"كل حاجة أخضر — من قاعدة البيانات لغاية محرّك الـOCR العربي."*

## السيناريو 2 — إضافة موظف بـOCR (3 دقائق)

**Story:** "شركة كويتية جديدة عيّنت موظف مصري. HR هيدخل بياناته من صورة البطاقة المدنية مباشرة."

**Actions:**
1. تبديل للتبويب الثاني — سجّل دخول كـ`hr` (`100000000002` / `hr12345`)
2. اذهب لـ `/employees` → اضغط "إضافة موظف جديد"
3. **الخطوة 1**: اسم = "زياد محمد فاروق"، رقم مدني = `305092002632`
4. **الخطوة 2**: اختر فرع + قسم
5. **الخطوة 3**: ارفع صورة البطاقة المدنية → اضغط "اقرأ"
   - يظهر JSON بكل الحقول: passport, nationality (EGY), birthdate, expiry
   - **اشرح**: "الأصفر يعني OCR شغّال، لكن راجع البيانات قبل الحفظ"
6. اضغط "طبّق على الفورم"
7. **الخطوة 4**: اترك ☑ "أنشئ حساب دخول تلقائيًا" → احفظ
8. **الخارج**: بطاقة صفراء بها username + password → اضغط "نسخ الاثنين"

**نقطة القوة:** *"من صورة بطاقة إلى موظف مكتمل + حساب دخول جاهز — في أقل من دقيقة."*

## السيناريو 3 — طلب إجازة كامل الدورة (3 دقائق)

**Story:** "الموظف الجديد يطلب إجازة. المدير يعتمد. الطلب يطبع رسمي."

**Actions:**
1. سجّل خروج → دخول كـ`employee` (بيانات الحساب اللي اتولّدت لتوّه)
2. تغيير كلمة السر (شاشة إلزامية)
3. `/requests` → **جديد** → نوع: إجازة سنوية
4. من: `اليوم` · إلى: `+3 أيام` · السبب: "مناسبة عائلية"
5. أرسل → يظهر في القائمة بحالة "معلّق"
6. تبديل لتبويب `manager` → `/tasks` → مهمة جديدة
7. افتح المهمة → اضغط "اعتماد"
8. الموظف يشوف الحالة تغيّرت لـ"معتمد"
9. المدير يضغط "طبع PDF" → يفتح ملف عربي منسّق مع QR code

**نقطة القوة:** *"الـPDF عربي حقيقي (RTL) — مش صور نصوص مقلوبة. والـQR بيتحقق من صحة الوثيقة."*

## السيناريو 4 — الحضور والانصراف (2 دقيقة)

**Story:** "بصمة QR للفرع + تعديل السجل من HR."

**Actions:**
1. `manager` → `/branches` → افتح branch → **QR للحضور**
2. اعرض الـQR على الشاشة
3. تبديل لـ`employee` → `/attendance` → امسح QR أو "بصم يدويًا"
4. يظهر السجل: `Punch In 10:23`
5. تبديل لـ`hr` → `/attendance-review` → اختر الشهر → **تصدير Excel**
6. يفتح Excel بـBOM عربي (Excel يقرأه صح)

---

## السيناريو 5 — الرواتب (2 دقيقة)

**Story:** "المحاسب يشغّل رواتب الشهر. المدير يعتمد. النظام يمنع تشغيل مكرّر بلا تسوية."

**Actions:**
1. تبديل لـ`accountant` → `/payroll`
2. اضغط **تشغيل الشهر الحالي** → يظهر ملخّص: 13 موظف، صافي X د.ك
3. الحالة: `prepared` — **مش نهائي**
4. تبديل لـ`manager` → نفس الصفحة → **اعتماد**
5. الحالة: `approved` → **finalize** → `locked`
6. حاول تشغيل تاني — النظام يرفض بـ409

**نقطة القوة:** *"دورة اعتماد فعلية — نفس اليوزر ما يقدرش يعتمد نفسه (فصل الواجبات)."*

## السيناريو 6 — نهاية الخدمة (1 دقيقة)

**Actions:**
1. `hr` → افتح موظف → **إنهاء الخدمة**
2. أدخل تاريخ + سبب → يحسب المكافأة تلقائيًا (قانون العمل الكويتي)
3. `hr` يحضّر → `accountant` يعتمد ماليًا → `hr` يسلّم عهدة → **موظف يقرّ**
4. تنفيذ نهائي → status = `terminated`

**نقطة القوة:** *"4 مراحل إلزامية — مش مجرد زر واحد. مضمون قانونيًا."*

---

## السيناريو 7 — الإدارة العليا + التدقيق (1 دقيقة)

**Actions:**
1. تبديل لـ`super_admin` → `/audit`
2. اعرض السجل: كل إجراء اتعمل في العرض دلوقتي مسجّل (login, terminate, payroll_lock)
3. `/system-health` مرة أخرى → أرقام العدّاد تغيّرت (طلبات +1, موظفون +1)

**الجملة الختامية:** *"النظام مش بس شغّال — كل خطوة قابلة للمراجعة والتدقيق. جاهز للاعتماد."*

## أسئلة متكرّرة قد يسألها العميل

**س:** هل يدعم أكثر من شركة على نفس النظام؟
**ج:** نعم — عزل كامل عبر `company_id`. صاحب الشركات يشوف كل شركاته، مدير الشركة يشوف شركته فقط.

**س:** الأمان؟
**ج:** JWT + 2FA (TOTP) للأدوار الحسّاسة + كل شيء مسجّل في `audit_log` + كلمات سر بـbcrypt + CSP + HSTS.

**س:** التخصيص؟
**ج:** 42 قالب طباعة قابلة للتعديل + 49 نوع طلب + سياسات حضور مخصّصة لكل فرع + توليد Employee ID برموز الشركة.

**س:** التكامل مع الأنظمة الحكومية؟
**ج:** جاهز — QR verification للوثائق المطبوعة، دعم قراءة MRZ الجواز والبطاقة المدنية، تصدير Excel متوافق مع منظومات العمل.
