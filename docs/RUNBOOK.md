## 1. النشر

**كيف يجري:** الرفع إلى `main` ← Railway يبني الصورة ← عند الإقلاع يُنفَّذ بالترتيب:

1. `python -m app.db_migrate` — يطبّق الترحيلات حتى الرأس. **إن فشل توقّف الإقلاع** (لا يُختم شيءٌ صامتًا).
2. `python -m app.bootstrap` — يصالح كتالوج الطلبات والصيغ، ويطبع في السجل ما صالحه وما خالف الشيفرة.
3. الخادم.

**قبل الرفع:** كل الاختبارات خضراء (`pytest -q -p no:randomly` في `backend`).

**بعد كل نشرة — إلزامي:**
```
backend/.venv/Scripts/python.exe backend/scripts/smoke_prod.py --expect <commit>
```
يتحقّق بلا كلمة مرور: النظام حيّ، النسخة المنشورة هي المتوقَّعة، البيئة production، الترحيل في القاعدة هو
آخر ترحيل في الشيفرة، النقاط المحروسة تردّ 401، لا ملفات أسرار ولا توثيق API مكشوف. **النتيجة يجب
أن تكون كلّها PASS.** ثم افتح النظام بحسابٍ واحد وتأكّد من لوحة التحكم.

## 2. المراقبة والتنبيهات

- **هوية النسخة:** `/api/manifest` — الالتزام، وقت البناء والنشر، البيئة، رقم الترحيل.
- **الصحة:** `/api/health` (عام)، وشاشة «صحة النظام» للمدير (فحص عميق للبيانات والترحيلات).
- **فشل المهام المجدولة** (المسح اليومي 6ص، مسح المهل كل ساعة، الملخص 8ص، **النسخ الاحتياطي 2:30ص**):
  يظهر مهمةً حرجة «فشل مهمة مجدولة: …» **لصاحب الشركات** في صندوق مهامه. لا بريد ولا تكامل خارجي.
- **السجلات:** من لوحة Railway (سجلات الخدمة). رسائل الإقلاع تبدأ بـ `[migrate]` و`[bootstrap]`.
- **غير متوفّر بعد:** مراقبة خارجية للتوفّر وتتبّع أخطاء (مثل Sentry) — انظر RELEASE_NOTES.

## 3. أعطال شائعة

| العرَض | السبب المرجّح | ما يُفعل |
|---|---|---|

## 4. خطة التراجع (Rollback) — DLV-26

**القاعدة الأولى: الإصلاح إلى الأمام أولى من التراجع.** إن كان العطل محدودًا، أصلحه وانشر التزامًا جديدًا —
فلا يضيع شيء. التراجع لعطلٍ يوقف العمل ولا يُصلَح بسرعة.

### أ) النشرة لم تُضف ترحيلًا

من لوحة Railway: **Deployments** ← النشرة السابقة السليمة ← **Redeploy**. ثم `smoke_prod.py --expect <الالتزام السابق>`.

لمعرفة هل أضافت النشرة ترحيلًا: قارن `migration_version` في `/api/manifest` قبل النشرة وبعدها، أو:
```
git diff --stat <الالتزام السابق> <الالتزام الحالي> -- backend/alembic/versions
```

### ب) النشرة أضافت ترحيلًا — بالترتيب

> **لماذا الترتيب:** الشيفرة القديمة لا تعرف ترحيل القاعدة الأحدث، فترفض الإقلاع
> (`Can't locate revision`). **قيس ذلك فعلًا** على نسخةٍ من التزامٍ أقدم.
> **وتحذير:** عكسُ الترحيل **يحذف ما أضافه** (أعمدةً أو جداول) ومعه بياناته — لذلك النسخة الاحتياطية أولًا.

1. **نسخة احتياطية الآن** (فوق النسخة الليلية):
   ```
   backend/.venv/Scripts/python.exe backend/scripts/backup_now.py
   ```
2. **اعرف رأس الترحيلات في الشيفرة القديمة** — هو `migration_version` الذي كان في `/api/manifest` قبل
   النشرة (سجّله قبل كل نشرة)، أو احسبه من الالتزام السابق:
   ```
   git worktree add ../hrms_old <الالتزام السابق>
   cd ../hrms_old/backend && ../../hrms_kuwait/backend/.venv/Scripts/python.exe -m alembic heads
   ```
   ثم احذف النسخة: `git worktree remove ../hrms_old`.
3. **اعكس القاعدة إليه — بالشيفرة الحالية** (فهي وحدها تعرف كيف يُعكَس ترحيلها)، ورابطُ قاعدة الإنتاج في
   `DATABASE_URL`:
   ```
   cd backend && DATABASE_URL="<رابط الإنتاج>" .venv/Scripts/python.exe -m alembic downgrade <رأس الشيفرة القديمة>
   ```
4. **أعد نشر الالتزام السابق** من لوحة Railway (Redeploy).
5. `smoke_prod.py --expect <الالتزام السابق>` — ويجب أن يطابق الترحيلُ في القاعدة رأسَ الشيفرة القديمة.

### ج) ما يضمن أن الخطة تعمل

- `tests/test_zzz_migrations_reversible.py` — في كل تشغيلٍ للاختبارات: قاعدةٌ جديدة بالترحيلات كلّها،
  ثم **عكسُ آخر عشرة وإعادتها** بلا خطأ. ترحيلٌ جديد بلا عكسٍ يعمل يُسقطه قبل أن يُنشر.
- وقيس الترتيب في ب) على التزامٍ أقدم حقيقي (2026-09-19): الشيفرة القديمة رفضت الإقلاع على القاعدة الأحدث،
  ثم أقلعت بعد عكس الترحيل بالشيفرة الحالية.
- **يلزم تمرينٌ على Postgres** (الاختبارات على SQLite): مرةً قبل التسليم على قاعدةٍ تجريبية، ويُسجَّل.

## 5. الحسابات والأسرار

- لا كلمات مرور في Excel أو المجموعات؛ كلمة مرور مؤقتة عشوائية لكل شخص وإجبار تغييرها.
- لا يُمنح أحدٌ `super_admin`؛ الإدارة لصاحب الشركات.
- **مفتاح التشفير `BACKUP_ENCRYPTION_KEY`** له نسخةٌ خارج Railway — بدونه لا تُفكّ أي نسخة.
- مفاتيح شاشات الحضور: تُدوَّر عند التسليم وعند الاشتباه بتسرّب (التدوير يُبطل كل رمزٍ قديم).
- `ALLOW_DEMO_RESET` **غير مضبوط** في الإنتاج. `ENABLE_API_DOCS` غير مضبوط إلا لحاجةٍ مؤقتة.
